RS — Week 1: Introduction to Recommender Systems

Focus

Recommender systems reduce information overload by suggesting relevant items to users. The class covered the five core recommender families, user/item data types, explicit vs implicit preferences, cold start, evaluation approaches, and ethical risks.

Key Concepts

  • Collaborative filtering — recommendation based on user similarity or user-item behaviour
  • Content-based filtering — recommendation based on item features or descriptions
  • Socio-demographic recommenders — uses age, location, profession, income, gender
  • Knowledge-based recommenders — uses explicit domain constraints and user requirements
  • Conversational recommenders — dialogue-driven preference elicitation
  • Explicit preferences — ratings, stars, likes, surveys, votes, reviews
  • Implicit preferences — clicks, watch time, purchase history, repeat visits
  • Cold start — insufficient history for personalised recommendations
  • Matthew effect — popular items become more popular through recommendation loops
  • Offline vs online evaluation — predictive metrics vs real-world satisfaction/adoption

Notes (live capture)

Definition:

  • Software tools/techniques that suggest items best suited to a user's interests
  • Designed around a specific item type: books, movies, restaurants, songs, courses, jobs
  • Core purpose: reduce information overload + decision fatigue

Business benefits:

  • Customer loyalty, trust, cross-selling, increased sales, better customer understanding

System data types:

  • Item data: cost, features, genre, length, tags, text, benefit
  • User profile: age, sex, location, profession, preferences, inferred model
  • Explicit: ratings, likes, stars, survey answers, votes, reviews
  • Implicit: browsing patterns, clicks, watch time, purchases, repeat visits

Five recommender families:

  • Collaborative — similarity between users or user-item behaviour → neighbourhood → prediction
  • Content-based — item features/descriptions → similar items to ones the user liked
  • Socio-demographic — uses demographic attributes (age, location, income, gender)
  • Knowledge-based — uses explicit domain constraints + user requirements
  • Conversational — dialogue to elicit preferences in real time

Collaborative filtering flow:

  1. Calculate similarity between target user and all others
  2. Form a neighbourhood of similar users
  3. Predict rating by aggregating neighbour ratings

Cold start:

  • No user/item/rating history → fallback to popular or regional trends
  • Example: new Netflix user → shown popular titles by region

Evaluation:

  • Offline: train/test splits, prediction metrics, before deployment
  • Online / user studies: satisfaction, interaction, adoption, real-world impact

Ethical risks:

  • Binge-watching, overconsumption, overspending, mindless scrolling
  • Idea segregation (filter bubbles), privacy concerns

ML Refresher (lecturer emphasis):

  • Supervised: regression (numerical target) or classification (categorical target)
  • Unsupervised: no labels, discovering hidden clusters
  • Deep learning: separate learning architecture, can still be regression/classification/unsupervised
  • Overfitting → dropout, weight decay, early stopping, cross-validation
  • Scaler must be fit on training data only to avoid data leakage
  • Class imbalance → oversampling, undersampling, SMOTE

import numpy as np

def rmse(y_true, y_pred):
    return np.sqrt(np.mean((np.array(y_true) - np.array(y_pred)) ** 2))

def mae(y_true, y_pred):
    return np.mean(np.abs(np.array(y_true) - np.array(y_pred)))

Flashcards (SR)

  • Q: What is the difference between personalised and non-personalised recommendation?

    • A: Personalised makes different recommendations per user using individual history/preferences. Non-personalised uses aggregate or group signals regardless of individual history.

  • Q: What is cold start, and which recommender type handles it best?

    • A: Cold start = insufficient user/item/rating history for personalised recommendations. Non-personalised popularity models handle it best since they need no individual history.

  • Q: Name the five recommender families introduced in Week 1.

    • A: Collaborative filtering, content-based, socio-demographic, knowledge-based, conversational.

  • Q: What is the Matthew effect in recommender systems?

    • A: Popular items get recommended more, making them even more popular — compounding advantage for already-popular items.

  • Q: Why must scalers be fit on training data only?

    • A: To prevent data leakage: fitting on all data lets the scaler see test-set information before evaluation, inflating performance estimates.

  • Q: Give one example where false negatives are worse than false positives.

    • A: Healthcare: missing a disease (false negative) is more dangerous than a false alarm (false positive).

  • Q: What is the relevance of implicit feedback in recommender systems?

    • A: It captures behaviour without requiring explicit user effort (clicks, watch time, purchases), making it abundant but noisier than explicit ratings.

  • Q: What ethical risks do recommender systems introduce?

    • A: Binge behaviour, overconsumption, overspending, filter bubbles/idea segregation, and privacy concerns from profiling user behaviour.
