Key Concepts

  • Text analytics / NLP — deciphering unstructured text into something analysable. Underpins LLMs, review mining, legal discovery, healthcare transcription, customer-support triage. Structured data is easy (missing values, dupes, joins); text needs deliberate, use-case-specific preprocessing.
  • NLTK — Natural Language Toolkit; free open-source Python package for natural-language algorithms (tokenizing, POS tagging, stemming, NER, sentiment, topic segmentation).
  • Tokenization — the preliminary step: break text into chunks (sentences, words, phrases, n-grams) and assign each a token. Sentence tokenizer (Punkt) splits into sentences; word tokenizer splits into words. Choice of granularity depends on the use case.
  • Frequency distribution (FreqDist) — counts how often each token occurs; .most_common(n) returns the top-n. Surfaces unique-word count vs total outcomes.
  • Word cloud — visual of token frequency (bigger = more frequent). Useful for spotting a document's central theme/top terms, but decorative — don't over-invest; back it with real algorithms, do 2–3-step analysis.
  • Stop words — high-frequency, low-information filler ("is, am, are, this, and, the, they"). Treated as noise; removed before further analysis. NLTK ships a per-language stop-word list in its corpus (you don't build it). NOT punctuation, NOT "words ending in a question mark."
  • Lexicon normalization — reducing morphological variants to a common form. Two flavours: stemming and lemmatization.
  • Stemming (Porter) — chops derivational affixes to a root. Fast, crude, can produce non-words. "connection/connected/connecting → connect" (good), but "city → citi", "awesome → awesom", "blue → blu", "fly → fli" (bad).
  • Lemmatization (WordNet) — maps to the dictionary base word (lemma) using vocabulary + morphology. Slower, linguistically correct. "fly → fly", ideally "better/best → good". Generally preferred over stemming; stemming only when resources/compute are tight.
  • POS tagging — assigns part-of-speech tags (noun, verb, adjective…) via NLTK's averaged-perceptron tagger. Tag set: NNP proper noun, VBD past-tense verb, VBN past participle, IN preposition, CD cardinal number, etc. Needs the averaged_perceptron_tagger download. One of many tagging schemes (Netflix has whole teams tagging genre/actors/location — a niche specialization).

Notes (live capture)

Why this matters for RecSys: content-based recommenders work on the actual content (text of items: news, descriptions, reviews). To compute similarity you first convert text → tokens → cleaned/normalized terms → vectors. Every preprocessing decision here feeds the term-document matrix and TF-IDF used in Class 2.

Pipeline order shown (a toolbox, NOT a mandatory sequence):

  1. Sentence tokenize — split paragraph into sentences (Punkt).
  2. Word tokenize — split into words.
  3. FreqDist — count word frequencies; inspect .most_common(5); plot distribution (matplotlib).
  4. Word cloud — quick visual of dominant terms.
  5. Stop-word removal — filter the token list against stopwords.words('english').
  6. Lexicon normalization — stemming and/or lemmatization.
  7. POS tagging — tag the surviving tokens.

The lowercase gotcha (the teaching moment): when filtering stop words, "The" survived because the stop-word list is all-lowercase and "The" != "the". Fix: lowercase the token before the membership test —

if w.lower() not in stop_words:
    filtered.append(w.lower())

This is the kind of silent bug that quietly corrupts a content-based pipeline (a stop word leaking into the term-document matrix inflates similarity on a meaningless term).

Stemming vs lemmatization — when each fails/wins:

  • On the demo sentence, stemming mangled city→citi, awesome→awesom, pinkish-blue→...blu — meaningless, so stemming was the wrong tool there.
  • But stemming isn't universally bad — it's faster and fine when compute is constrained and exactness doesn't matter.
  • Lemmatization gave flying→fly (correct) vs stemming fly→fli (wrong). For "better/best → good" you need a richer lemmatizer; the lightweight WordNet default may return the word unchanged (less cognitive load = shallower mapping).
  • Both operate on words (post-tokenization), confirmed in Q&A — not on whole sentences.

Use-case-driven preprocessing (the recurring warning):

  • No universal recipe — customer-support data, reviews (Yelp/Airbnb/Twitter), legal docs, clinical notes, novels each need a different subset of steps.
  • Language matters: English is simple (no gendered objects); French/Spanish/Hindi/Mandarin add gendered nouns and richer morphology — students who pick a language they don't speak get stuck at preprocessing.
  • Advice for final projects: pick complete, easy-to-work-with data (reviews, tweets) over domains needing expert knowledge (legal, healthcare) unless someone on the team has that background.

Group exercise set: pick any online text (Wikipedia, tweets, reviews), then run the full chain — sentence + word tokenize → stop-word filter → stemming → lemmatization → POS tagging → inspect the word cloud and interpret. Goal: be able to apply preprocessing to any text before touching sentiment/classification.

Math / Code

import nltk
nltk.download('punkt'); nltk.download('stopwords')
nltk.download('wordnet'); nltk.download('averaged_perceptron_tagger')

from nltk.tokenize import sent_tokenize, word_tokenize
from nltk.probability import FreqDist
from nltk.corpus import stopwords
from nltk.stem import PorterStemmer, WordNetLemmatizer

text = "Hello Mr. Smith, how are you doing today? The weather is great, and the city is awesome."

sents  = sent_tokenize(text)          # 1. sentences
tokens = word_tokenize(text)          # 2. words
fdist  = FreqDist(tokens); fdist.most_common(5)   # 3. frequencies

stop = set(stopwords.words('english'))            # 5. stop-word removal
filtered = [w.lower() for w in tokens if w.lower() not in stop]   # NOTE: lowercase BEFORE the test

ps, lem = PorterStemmer(), WordNetLemmatizer()    # 6. lexicon normalization
stemmed     = [ps.stem(w)      for w in filtered]   # fast, crude  (fly->fli)
lemmatized  = [lem.lemmatize(w) for w in filtered]  # correct base (fly->fly)

nltk.pos_tag(word_tokenize("Albert Einstein was born in Germany in 1879."))   # 7. POS
# -> [('Albert','NNP'),('Einstein','NNP'),('was','VBD'),('born','VBN'),
#     ('in','IN'),('Germany','NNP'),('in','IN'),('1879','CD'),('.','.')]

POS tags worth memorising: NNP proper noun · VBD past-tense verb · VBN past participle · IN preposition · CD cardinal number.

Flashcards (SR)

  • Q: Why is preprocessing the step students lose marks on?

    • A: It's use-case-specific and easy to skip; a content-based/text project with sloppy tokenization, stop-word, or normalization steps produces a corrupted term-document matrix and meaningless similarities.

  • Q: Tokenization — what and what granularities?

    • A: Breaking text into chunks and assigning tokens; granularity = sentences, words, phrases, or n-grams (1-gram, bigram…), chosen by use case.

  • Q: What are stop words and where does the list come from?

    • A: High-frequency, low-information filler ("the, is, and"); treated as noise and removed. NLTK ships a per-language list in its corpus — you don't build it.

  • Q: The lowercase gotcha?

    • A: Stop-word list is lowercase, so "The" != "the" and survives filtering. Fix: w.lower() before the membership test.

  • Q: Stemming vs lemmatization?

    • A: Stemming chops affixes to a root — fast, crude, can make non-words (fly→fli, city→citi). Lemmatization maps to the dictionary base word using vocabulary+morphology — slower, correct (fly→fly, better→good). Prefer lemmatization; stem only when compute is tight. Both operate on words.

  • Q: POS tags — NNP, VBD, VBN, IN, CD?

    • A: Proper noun, past-tense verb, past participle, preposition, cardinal number.

  • Q: Is the preprocessing pipeline a fixed sequence?

    • A: No — it's a toolbox; pick a subset per use case (reviews ≠ legal ≠ a novel; English ≠ gendered/morphologically rich languages).
