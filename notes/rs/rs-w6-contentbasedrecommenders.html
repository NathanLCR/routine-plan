Key Concepts

  • Content-based recommendation — recommends using the actual content of items (text/keywords/descriptions) via similarity, not user history. Needs content; uses similarity (and diversity) to rank.
  • Personalized vs non-personalized — personalized = per-individual from their characteristics/preferences; non-personalized = general group behaviour (popularity, trending), ignores individual history. Class focused on non-personalized (easier, fewer data needs).
  • Three non-personalized families — (a) aggregate opinions (all users' prefs, e.g. Netflix); (b) product-association recommenders (item-item relations, e.g. Amazon); (c) description-based (NLP on item text, e.g. chatbots).
  • Vector space model — represent each item/document as a vector; dimensions = terms (keywords/features); entries = how often each term appears. Find nearest documents by angle.
  • Term-document matrix — rows = terms (features you extract), columns = documents; cell = term frequency in that document. Feature extraction quality makes or breaks the recommender.
  • TF (term frequency) — raw count of a term in a document.
  • Normalization — scale counts (→ 0–1) so long documents and high-count terms don't dominate; converts absolute differences to relative ones, gives recommendation fairness.
  • IDF (inverse document frequency) — log(N / df): down-weights terms appearing in many documents (they don't discriminate). A term in all documents → IDF = 0 → dropped.
  • TF-IDF — normalized TF × IDF. Net effect: kills (1) over-long documents [normalization] and (2) ubiquitous useless terms [IDF]. The resulting weighted table is what you recommend from.
  • Binary representation — instead of counts, 1/0 for present/absent. Used for short docs (tweets) and to cut computation. TF-IDF still zeroes out the all-documents terms.
  • Cosine similarity — cos θ = (A·B) / (|A||B|). Angle between two document vectors; 0–1. The day's main similarity metric.
  • Diversity — recommending only the most-similar item is often useless (bought a water bottle → don't recommend another bottle). Balance similarity with deliberately dissimilar picks.
  • Shimazu algorithm — picks 3 recommendations: C1 = most similar, C2 = most dissimilar, C3 = most dissimilar to both C1 and C2 (balances similarity + diversity).
  • Overfitting — model memorizes training data, fails on new content. Mitigate: train/test split (80/20, 70/30), k-fold CV (k=3 typical; too many folds on small data → low accuracy), leave-one-out.
  • Precision / recall / F1 — evaluation beyond accuracy. Use when classes are imbalanced (fraud at ~1% → 98% accuracy is terrible) or when false-positives vs false-negatives have asymmetric cost (medical = avoid mistakes; actionable decisions → recall). F1 balances precision & recall.

Part 2 — Content-based recommendations

Where it sits / when to use it:

  • Traditional applications: news articles, web pages, movies, books. Doesn't need a user profile — recommends items similar to what you mentioned.
  • Advantages: easy to implement (little data on the person); handles new items (cold start — a new item can still be recommended); can recommend niche items (the opposite of ARM, which kills niche items via the support threshold).
  • Disadvantages: limited by feature-extraction quality (bad similarity features → bad recommender); doesn't distinguish high/low-quality items — no ranking/quality distinction.
  • Real systems (Netflix/Amazon) combine content-based + ARM + collaborative — not one type.

TF-IDF build (the pipeline to reproduce):

  1. Build term-document matrix (raw TF counts).
  2. Normalize TF (0–1) — kills domination by long docs / high-count terms; relative not absolute.
  3. Compute IDF = log(N/df) per term — a term in all docs → 0 (useless for discrimination).
  4. TF-IDF = normalized TF × IDF → new weighted table; recommend from this.
  5. (Short docs) use binary TF (1/0) to reduce computation; TF-IDF still zeroes ubiquitous terms.

Cosine similarity — interpretation guide (memorise):

  • cos θ = 1 → angle 0° → identical/very similar (same direction).
  • cos θ ≈ 0.5–1 → moderately similar.
  • cos θ = 0 → 90° → completely dissimilar/orthogonal.
  • < 0 → opposite. Compute similarity for every document pair; new document → find nearest (or, with Shimazu, nearest + farthest + balance).

Diversity & Shimazu: similarity-only recommendations are often weak (another water bottle). Shimazu returns C1 most similar, C2 most dissimilar, C3 most dissimilar to both → similarity + diversity balance. Movies tolerate high similarity (similar-but-different stories); shopping often wants diversity.

Evaluation:

  • Overfitting → 80/20 or 70/30 split; k-fold CV (k=3 typical); leave-one-out. Don't trust a single grid-search result — repeat and average (averaged accuracy is usually lower but honest).
  • Beyond accuracy: precision, recall, F1. Imbalanced data (fraud ~1% → 98% accuracy worthless) and asymmetric error costs (medical → minimize mistakes; actionable → recall) demand these. F1 balances the two. (Same lesson as NLP CA1: per-class P/R/F1 + confusion matrix, not accuracy.)

Math / Code

# --- TF-IDF ---
# TF_norm(t,d) = count(t,d) / sum_k count(k,d)        # normalize: kill long-doc / high-count domination
# IDF(t)       = log10( N / df(t) )                    # df = #docs containing t; in-all-docs -> 0
# TFIDF(t,d)   = TF_norm(t,d) * IDF(t)                 # recommend from this weighted table
# Binary TF: 1 if present else 0  (short docs / less compute) — TFIDF still zeroes ubiquitous terms

# --- Cosine similarity ---
import numpy as np
def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))
# interpret: 1 identical · ~0.5–1 moderate · 0 orthogonal/dissimilar · <0 opposite

# Verified class example:
cosine([3,0,2,5], d2_with_dot31_mag_sqrt30)   # -> 0.92  (similar)

# --- Shimazu (diversity) ---
# C1 = argmax cosine(query, c)                 # most similar
# C2 = argmin cosine(query, c)                 # most dissimilar
# C3 = argmax_c [ d(c,C1) + d(c,C2) ]          # most dissimilar to BOTH

    • A: Personalized = per-individual from their preferences; non-personalized = group behaviour (popularity/trending), ignores individual history. Class focused on non-personalized.

  • Q: Cosine similarity formula and interpretation?

    • A: cos θ = (A·B)/(|A||B|), range 0–1. 1 = identical (0°); ~0.5–1 moderate; 0 = orthogonal/dissimilar (90°); <0 opposite.

  • Q: What does normalization fix in TF, and IDF?

    • A: Normalization scales counts to 0–1 so long docs / high-count terms don't dominate (relative not absolute). IDF = log(N/df) down-weights terms in many docs; a term in all docs → IDF 0 → dropped.

  • Q: TF-IDF net effect?

    • A: Removes (1) over-long-document bias [normalization] and (2) ubiquitous non-discriminating terms [IDF]; the weighted table is what you recommend from.

  • Q: Shimazu algorithm — the three picks?

    • A: C1 = most similar, C2 = most dissimilar, C3 = most dissimilar to both C1 and C2. Balances similarity and diversity.

  • Q: Content-based advantages vs disadvantages?
