RS — Week 5: Association Rule Mining (Market Basket Analysis)

Focus

Association Rule Mining (ARM) as a recommender-system type: unsupervised mining of if-A-then-B rules from transaction data via the Apriori algorithm's three metrics — support, confidence, lift. Delivered by a substitute (Nitya off sick; her slides). Sharpest point of the class: threshold choice is not a technicality — it's the discussion section. "Some of you are gonna get 80%, some 50%. It's about the discussion, not the code." Pick a business goal first, derive thresholds from it, and be able to defend every number.

Key Concepts

  • Association Rule Mining (ARM) — unsupervised data-mining technique that discovers relationships (rules A → B) between items in large transactional datasets.
  • Rule — directed association A → B with attached support/confidence/lift values. Direction matters for confidence (Burger→Ketchup ≠ Ketchup→Burger).
  • Support(B) — popularity: fraction of all transactions containing B.
  • Confidence(A→B) — reliability: fraction of A-transactions that also contain B. Inflated by B's popularity.
  • Lift(A→B) — confidence corrected for B's base rate: Confidence(A→B) / Support(B). >1 positive association; ≈1 independent; <1 negative; >3 strong.
  • Apriori algorithm — standard ARM algorithm: count itemsets → filter by min support → filter by min confidence → rank surviving rules by lift.
  • Combinatorial explosion — with 121 items, pairwise combinations alone are unmanageable without threshold pruning; that's why thresholds exist.
  • Market basket analysis — ARM applied to shopping carts; today's dataset: ~7,500 store transactions.
  • RecSys taxonomy (so far) — ranking/popularity-based (W2–W3), content-based (keywords/NLP), ARM (associations), collaborative filtering (upcoming). Real systems (Netflix, Amazon, Spotify) combine several — know the names and when each applies.

Notes (live capture)

Where ARM sits:

  • Unsupervised learning — no labels, no train/test split. Siblings: k-means clustering (upcoming), dimensionality reduction (PCA, last semester), anomaly detection.
  • Usually a starting point, not the end goal: rules → features/labels → supervised model downstream (e.g. churn prediction, early diagnosis). "Unsupervised is usually the start."
  • Differs from generic ML: each recommender type exists for a specific business reason (popularity vs content vs association), not interchangeable like RF/XGBoost on tabular data.

Worked example (slides — memorise the numbers):

  • 1,000 transactions; 100 contain ketchup, 150 contain burger, 50 contain both.
  • Support(Ketchup) = 100/1000 = 10%.
  • Confidence(Burger→Ketchup) = 50/150 = 33.3%.
  • Lift(Burger→Ketchup) = 33.3% / 10% = 3.33 → strong association.

Business actions once a rule is found: colocation (shelf placement), targeted advertising, collective/bundle discounts, packaging. Evaluation is two-stage: offline metrics during build + online tracking in production (clicks, sales uplift) — recommenders are judged in the real world, not just on held-out data.

Threshold guidance (Optimizing ARM PDF — exam/CA reference):

  • Large datasets: support 1–5%, confidence 50–80%. Small datasets: support 10–20%, confidence 70–90% (in a small dataset everything looks "popular"; raise the bar).
  • Retail: support 1–5%, conf 50–80%. Fraud/rare events: support 0.1–1%, conf 90%+ — fraud is rare (low support unavoidable) but a false accusation is costly (demand high confidence). Medical: support 5–10%, conf 70–95%.
  • Practical loop: start ~5% support / 60% confidence → run → too many rules? raise support; too few? lower it → rank survivors by lift → fine-tune with domain knowledge.
  • Class-observed failure modes: threshold too loose → junk rules (bug spray ↔ bread); too tight → only the single most popular item survives (one team at support 0.4 got shrimp-only recommendations) and everything else gets zero recommendations even when good rules exist.

How to answer "how does Apriori work?" (explicitly flagged as a presentation question for CA work):

  1. Count all items and all candidate combinations (combinatorial explosion motivates the rest).
  2. Compute support; prune unpopular itemsets (justify the threshold).
  3. Compute confidence on survivors; prune weak rules (justify the threshold).
  4. Rank by lift — but don't rank blindly: a tight threshold can leave only shrimp-rules, starving every other product of recommendations.

    5. Answering "it recommends things based on other products" = fail. Walk the four steps with the why.

Math / Code

# Support(B)        = |T(B)| / |T|
# Confidence(A→B)   = |T(A ∧ B)| / |T(A)|
# Lift(A→B)         = Confidence(A→B) / Support(B)
#                   = P(B|A) / P(B)   → base-rate-corrected confidence
# Note: Lift is symmetric — Lift(A→B) = Lift(B→A); confidence is not.

def support(item_B, records):
    return sum(item_B in r for r in records) / len(records)

def confidence(item_A, item_B, records):
    with_A = [r for r in records if item_A in r]
    return sum(item_B in r for r in with_A) / len(with_A)

# Full pipeline in two lines (apyori):
from apyori import apriori
rules = list(apriori(records, min_support=0.0045, min_confidence=0.2,
                     min_lift=3, min_length=2))
# min_support=0.0045 ← "bought 5×/day": 5*7=35 / 7500 weekly txns

Flashcards (SR)

  • Q: Formula and meaning of support, confidence, lift?

    • A: Support(B)=|T(B)|/|T| (popularity); Confidence(A→B)=|T(A∧B)|/|T(A)| (reliability of the rule); Lift(A→B)=Confidence(A→B)/Support(B) (association corrected for B's base rate).

  • Q: Interpret lift values.

    • A: >1 positive association; ≈1 independent (coincidence); <1 negative association; >3 strong rule. Symmetric: Lift(A→B)=Lift(B→A).

  • Q: Burger/ketchup worked example (1000 txns, 100 ketchup, 150 burger, 50 both)?

    • A: Support(K)=10%; Confidence(B→K)=50/150=33.3%; Lift=3.33.

  • Q: Four steps of Apriori?

    • A: 1) set min support/confidence thresholds, 2) extract itemsets above min support, 3) keep rules above min confidence, 4) order rules by descending lift.

  • Q: Why low support but very high confidence for fraud detection?

    • A: Fraud is rare → can't demand popularity (support 0.1–1%); false accusations are costly → demand 90%+ confidence before flagging.

  • Q: Threshold guidance: large vs small datasets?

    • A: Large: support 1–5%, conf 50–80%. Small: support 10–20%, conf 70–90% — in small data everything is "popular", so raise the bar.

  • Q: Where did min_support=0.0045 come from in the notebook?

    • A: Business statement "item bought 5×/day" → 35/week ÷ ~7,500 weekly transactions ≈ 0.0045. Thresholds derive from goals, not guesses.

  • Q: What ML category is ARM and what's its usual role in a pipeline?

    • A: Unsupervised learning (no labels, no train/test split). Usually a preprocessing/insight step — rules become features or labels for downstream supervised models.

  • Q: Failure modes of bad thresholds?

    • A: Too loose → junk rules (bug spray↔bread), combinatorial overload. Too tight → only the most popular item survives (shrimp-only recommendations), other products get nothing.
