RS — Week 4: Data Understanding (EDA & Descriptive Statistics)

Focus

A deliberate detour away from recommender models: the lecturer (Nitya Govindaraju) walked two notebooks — data visualisation and descriptive statistics — to force one discipline before anyone touches a model: understand your data first, or every downstream choice is guesswork. Two ideas carry the whole session and will be examined in coming classes. First, distribution shape dictates your missing-value strategy — normal → mean/median/mode are interchangeable; skewed → use the median, because the mean is dragged by the tail and will distort the feature space. Second, and hammered repeatedly with the penguin and treadmill data, correlation is not causation — a positive scatter slope tells you variables move together, never that one drives the other. Practical CA1 takeaway: run .corr()/heatmap on your chosen dataset before committing — weak correlations everywhere = a weak dataset = garbage-in/garbage-out, and you should check collinearity to drop redundant features. (She explicitly warned that students have failed projects on exactly these EDA mistakes.)

Key Concepts

  • Variable typing — numerical splits into continuous (decimals, e.g. total_bill, tip = currency) and discrete (counts, e.g. size = people at a table); categorical splits into nominal (no order: sex, smoker) and ordinal (ordered: day). time (lunch/dinner) can be either — treated nominal here. Typing drives which plots and stats are valid.
  • .describe() — descriptive (not inferential) stats: count, mean, std, min, 25/50/75th percentile (IQR), max — numerical columns only. Add include='all' to also get categorical summaries (count, unique, top, freq).
  • .info() vs .describe() — .info() = structure (dtypes, non-null counts, memory); .describe() = statistical summary. Different jobs.
  • Confidence interval on a bar — the black cap on a sns.barplot bar is the CI of the estimate, not an outlier marker.
  • Univariate vs bivariate — univariate = one variable's distribution (histogram, countplot, KDE, boxplot); bivariate = relationship between two (scatter, pairplot off-diagonal, correlation).
  • Skew & central tendency order — normal: mean = median = mode (centre); positive (right) skew: mode < median < mean; negative (left) skew: mean < median < mode. The long tail pulls the mean.
  • Box plot anatomy — box = IQR (25th–75th), centre line = median, whiskers = range, isolated dot = outlier. "A histogram in a different format."
  • Pair plot — grid over numerical columns; diagonal = histograms (univariate), off-diagonal = scatterplots (bivariate). Discrete×continuous axes give striped scatter columns.
  • Correlation coefficient (.corr()) — range −1 to +1; diagonal = 1 (variable vs itself). |r| near 1 = strong, near 0 = no linear relationship. Working benchmark: |r| > 0.5 carries weight.
  • Collinearity / multicollinearity — when one predictor is derivable from others (height + weight ⇒ BMI). Redundant → drop via feature selection/engineering. Checked alongside X→Y correlation.
  • Correlation ≠ causation — co-movement (correlation) must not be read as one variable causing the other; causation needs further investigation / domain knowledge.

Notes (live capture)

Why this session exists:

  • "If you don't understand your data and jump straight to models, it's problematic." Data understanding decides which model is even applicable.
  • Datasets used are built into seaborn (sns.load_dataset): tips, titanic, penguins; plus an uploaded treadmill case-study CSV.

Inspection workflow (Pandas):

  • .head() / .tail() → eyeball rows. tips = 244×7; treadmill = 180×9; titanic = 891×15; penguins has missing values.
  • .shape → (rows, cols). .info() → dtypes + non-null counts. .describe() → numerical stats; .describe(include='all') → adds categorical (top = most frequent value, freq = its count). For the exercises she drops categoricals and keeps numerical only.

Visualisation — match the plot to the variable type:

  • Bad example to avoid: tips.plot.bar(x='smoker', y='tip') over 244 rows → unreadable wall of bars/noise. (Nathan flagged it: bars too wide/dense to read.) Students do submit plots like this.
  • Fix: groupby('smoker').mean() then bar-plot the aggregated means (total_bill, tip, size).
  • Library ladder: pandas built-in → matplotlib → seaborn (cleanest). sns.barplot(data=tips, x='smoker', y='total_bill') is a one-liner; matplotlib needs manual value/index assignment first.
  • Stale code warning: a matplotlib line that worked 2 years ago now breaks (module changes) — always verify reused GitHub/old code still runs.
  • hue= adds a second categorical split (e.g. barplot(x='smoker', y='total_bill', hue='sex')) for grouped comparison.

Count plots (titanic):

  • sns.countplot(data=titanic, x='sex') = one-step; matplotlib equivalent needs value_counts().values → values, .index → labels, then plt.bar.
  • hue='class' → reads as "more males than females, and third-class males dominate." Counts only — no magnitude.

Histograms & skew (tips → total_bill):

  • bins is a tunable hyperparameter (use suggested values or experiment). total_bill spans ~5–50, most bills 10–20 → positive skew.
  • Why it matters — missing-value imputation: normal distribution → mean = median = mode, any works. Positive skew → applying the mean distorts the feature space; default to the median (mode often isn't even in .describe(), so median is the safe fallback). Always check distribution shape before imputing.

Pair plot & the correlation≠causation lesson (penguins):

  • 4 numerical: bill_length, bill_depth, flipper_length, body_mass. Diagonal histograms → judge skew per variable (bill_length ≈ normal, others slight skew).
  • Off-diagonal scatter → slope = correlation direction. The trap: a positive body_mass vs bill_length slope does NOT mean mass causes longer bills. Human analogy she used: more body mass doesn't make your hand longer. Correlation only; causation needs investigation / being a domain ("penguin") expert.
  • hue='island' (Torgersen, Biscoe, Dream) + kind='reg' → per-group regression lines. Correlation strength varies by group, and a group can flip the sign: bill_depth vs body_mass is positive for Torgersen/Dream but negative for Biscoe. Aggregating across groups hides this (a Simpson's-paradox flavour). Adding a categorical dimension also changed the per-island skew vs the pooled view.

Correlation matrix & heatmap (penguins):

  • df[num_cols].corr() → coefficient table (diagonal 1). sns.heatmap(corr, annot=True) to read visually.
  • Strong: flipper_length vs body_mass = 0.87. Moderate: bill_length vs flipper ≈ 0.66, bill_length vs body_mass ≈ 0.6. Weak/negative: bill_length vs bill_depth ≈ −0.24.
  • Why test correlation at all: (1) linearity check before regression — no linearity ⇒ linear regression is wrong, use non-linear models; (2) X→Y influence direction/strength; (3) X1↔X2 collinearity → drop redundant features (height/weight/BMI example). Class struggled badly to read the heatmap — she stressed this is foundational and a common failure point.

Treadmill case study (descriptive-statistics notebook):

  • 180×9: Product (TM195/498/798), gender, age, education(yrs), marital status, usage(/week), fitness(1–5), income, miles.
  • .describe() / include='all'; histogram per numerical column (pandas .hist()).
  • Box plot sns.boxplot(x='gender', y='age'): IQR box, median line (male & female medians ≈ similar), whiskers ≈ ranges, one female outlier at age 50.
  • Crosstab pd.crosstab(product, gender) → counts; TM798 skews male, TM195 even. Same info as countplot(x='product', hue='gender').
  • Pivot table pivot_table(index=['product','gender'], columns='marital_status', aggfunc=len) → counts (repeated numbers = a tell you used len, not the column's real values). Swap to values='income' → actual segment income. TM798 income ~58–84K (higher, wider spread); TM195/498 below 50K, tighter.
  • Interpretation drill → assumptions, then dismantled them:
  • Defensible: "TM798 is the premium/expensive model — higher-income buyers self-select; lower-income can't afford it." Plausible correlation-backed read.
  • Rejected as causation overreach: "fit people earn more" / "running more → earning more" (reverse-causation just as likely; an unemployed person can still run), and "single males run more" ignored the count/distribution (more partnered users overall, but lower per-head miles — averages hide the split).
  • Treadmill heatmap: range 0→+1 (no negative correlations here) so always read the actual range first, not the textbook −1→1. Strong: fitness–miles ≈ 0.79, plus usage–miles and usage–fitness. Moderate: age–income ≈ 0.51, miles–income ≈ 0.54. The "fitness-conscious people earn more" hunch sits at only moderate — not worth deeper investigation unless you segment by a category first.
  • Closing warning: a past student had ~24 variables all with r ≈ 0.00–0.06 → no signal → model returns garbage. Test correlation strength to judge whether a dataset is even usable.

Self-test Q&A

  • Q: .info() vs .describe() — difference?

    • A: .info() = structure/dtypes/non-null/memory; .describe() = numerical summary stats (mean, std, percentiles). include='all' extends .describe() to categoricals.

  • Q: Bar has a black cap — outlier?

    • A: No. Confidence interval of the estimate.

  • Q: Feature is right-skewed with missing values — impute with mean, median, or mode?

    • A: Median. Mean is pulled by the tail and distorts the distribution; mode is often unavailable in .describe().

  • Q: Scatter of body_mass vs bill_length has a positive slope. Valid conclusion?

    • A: They're positively correlated. NOT that one causes the other — correlation ≠ causation.

  • Q: Why run a correlation heatmap before modelling?

    • A: To test linearity (justifies linear vs non-linear regression), gauge each predictor's relationship to the target, and detect collinearity so redundant features can be dropped.

  • Q: Heatmap shows |r| ≈ 0 across all variables — implication?

    • A: Weak dataset, no usable signal; the model will return noise. Reconsider the dataset/features.

  • Q: Box plot — what do box, line, whiskers, and a lone dot mean?

    • A: Box = IQR (25–75th), line = median, whiskers = range, dot = outlier.
