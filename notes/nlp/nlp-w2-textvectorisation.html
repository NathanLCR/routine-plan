NLP — Week 2: Text Vectorisation & Representation

Focus

How to turn unstructured text into numeric vectors for classification — the four bag-of-words encodings (frequency, one-hot, TF-IDF, distributed) and the libraries that implement them (scikit-learn, NLTK, Gensim). TF-IDF is the benchmark; distributed representations (Word2Vec/Doc2Vec/GloVe/BERT) capture meaning that BoW cannot. The lecturer's sharpest practical points: TF-IDF is your AI Studio benchmark and a strong general-purpose starting point, and BoW's fatal weakness is that "dog bites man" and "man bites dog" get identical vectors — order and semantics are lost. Critical compliance warning: NLP CA1 is AI-use Level 2 — no AI-generated content in the final submission (see flags).

---

Key Concepts

  • Token — a string of encoded bytes representing meaning; "not quite a word." CountVectorizer/TfidfVectorizer treat any whitespace-separated string as a token → a feature/column.
  • Bag of words (BoW) — each document = a vector of length = vocabulary size; meaning assumed encoded in vocabulary. Term-document matrix.
  • Frequency vectors — raw token counts (CountVectorizer) or term frequency (count normalised by document length).
  • One-hot encoding — binary: 1 if token present, 0 if absent. Good for short docs (tweets), and for ANNs with sigmoid [0,1] / tanh [-1,1] activations and RNNs.
  • TF-IDF — weights a token by how rare it is across the corpus; the AI Studio benchmark. TF = nₖ/n, IDF = log₂(N/Nₖ), TF-IDF = TF·IDF.
  • n-grams — multi-token features ("machine learning", "text mining" = 2-grams). Hyperparameter ngram_range=(1,2).
  • Stemming vs lemmatisation — stemming = crude suffix chop ("caring"→"car"); lemmatisation = dictionary root with POS/context ("caring"→"care"). Lemmatisation keeps meaning, costs more.
  • Stop-word removal — drop "the/is/of"; TF-IDF does this implicitly (common words get tiny weights).
  • Cosine similarity — cos θ = (A·B)/(‖A‖‖B‖); angle-based similarity of two vectors. (Distance = 1 − cos θ; see flag for the transcript muddle.)
  • Distributed representation — learned dense embeddings where similar words/docs sit close in space; Word2Vec, Doc2Vec, GloVe, BERT/GPT.
  • CRISP-DM — the 6-stage process the CA1 report must follow: Business Understanding → Data Understanding → Data Preparation → Modelling → Evaluation → Deployment.

Notes (live capture)

Why text is hard:

  • Average professional vocabulary ≈ 60k words = only ~10% of the Oxford dictionary, ~5% of what Google recognises (Bengfort et al., 2019).
  • Ambiguity, polysemy ("crab" = animal / nebula), meaning drift over time ("battery"), culture/context dependence, grammar (prefixes/suffixes don't add meaning but explode the token count).
  • Early approach treated language like a compiler (Chomsky/grammar) — failed. Statistical ML fits the fuzziness better.
  • English/French/German/Arabic/Chinese are mature; low-resource languages (e.g. Amharic) lack tooling → research opportunity.

Pre-processing sequence (do before vectorising):

  • Tokenise → remove punctuation/emojis → lowercase → stop-word removal → filtering (consolidate synonyms e.g. bike/bicycle) → stem or lemmatise. Only then vectorise.

Four BoW encodings:

  1. Frequency — CountVectorizer. Counts. Required first step even if you reweight later (and for word clouds). Suffers Zipfian long tail.
  2. One-hot — Binarizer after a count, or CountVectorizer(binary=True). Did the token occur? Loses per-word similarity ("trying"/"try" as distant as "red"/"bicycle").
  3. TF-IDF — TfidfVectorizer (= CountVectorizer + TfidfTransformer). Rare-overall-but-frequent-here → high weight (the Google-search intuition). The benchmark.
  4. Distributed — Word2Vec/Doc2Vec via Gensim (NLTK/sklearn don't implement these). Continuous dense vectors capturing meaning.

Libraries (lecturer's take):

  • scikit-learn — cleanest/most interpretable for vectorising; her preference. Not built for text but robust API.
  • NLTK — more powerful for linguistics, trickier syntax; TextCollection for TF-IDF, needs the whole corpus.
  • Gensim — doc2bow, TfidfModel, Word2Vec/Doc2Vec; serialises to disk; doesn't tokenise/stem. Comes with a Google-news pre-trained model.
  • Code samples for all three are in a zipped folder on Moodle.

Dimensionality:

  • BoW is huge & sparse. Cap features (max_features; benchmark = 1000 in AI Studio, slides use 5000). HashingVectorizer for very large corpora (no inverse transform, no IDF).
  • Reduce with PCA (eigen-decomposition of covariance; needs normalised data) or SVD (PCA is a special case of SVD). Lecturer's anecdote: TF-IDF → PCA → Random Forest beat other approaches on fake-news detection. UMAP (graph-based) is an untried-by-her option worth exploring.

Balancing: Classification needs balanced classes. Undersample to the minority count (she prefers it). Must vectorise before SMOTE — "you can't meaningfully SMOTE unvectorised text."

Distributed representations:

  • Word2Vec (Mikolov et al., 2013, Google) — CBOW or skip-gram; king − man + woman ≈ queen; capitals cluster near countries.
  • Doc2Vec — paragraph vector; fixed-length vectors from variable-length docs; respects local word order (n-gram-like); lower dimensionality than BoW.
  • GloVe — co-occurrence-probability ratios (graph/count-based, not skip-gram).
  • BERT / GPT — transformer embeddings; current best. "LLMs are super expert at embeddings."
  • t-SNE / PCA used to project high-dim embeddings to 2D for visualisation.

RAG / question-answering (lecturer described it directly — dissertation-relevant):

  • Embed the question with an LLM → store question→answer truth pairs in a vector database → embed a new question → cosine similarity retrieves the closest → feed that answer to the LLM to generate language.
  • She named RAGAS ("recently published, 2025") as a system of metrics for "my LLM generated this, my truth is this — how good is it?" and for comparing two LLMs. (Dating slip — see flag.)

Math / Code

# --- TF-IDF (the benchmark) ---
# TF   = n_k / n           n_k = count of token k in doc, n = total tokens in doc
# IDF  = log2(N / N_k)     N = #docs in corpus, N_k = #docs containing token k
# TFIDF = TF * IDF         rare-overall but frequent-here -> high weight

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression

tfidf = TfidfVectorizer(
    max_features=5000,        # cap dimensionality (AI Studio benchmark used 1000)
    stop_words="english",     # TF-IDF also down-weights stopwords implicitly
    ngram_range=(1, 2),       # experiment: 1-gram vs 2-/3-gram (Enron emails needed 3)
)
X = tfidf.fit_transform(corpus)       # sparse ((doc, term) -> tfidf)
clf = LogisticRegression().fit(X, y)

# --- Cosine similarity (similarity, NOT distance) ---
#   cos(θ) = (A·B) / (||A|| * ||B||)
#   +1 = same direction (most similar) | 0 = orthogonal (unrelated) | -1 = opposite
#   cosine DISTANCE = 1 - cos(θ).  For non-negative BoW vectors cos∈[0,1], dist∈[0,1].
from sklearn.metrics.pairwise import cosine_similarity
sim = cosine_similarity(X[0], X[1])

Flashcards (SR)

  • Q: TF-IDF formula?

    • A: TF = nₖ/n, IDF = log₂(N/Nₖ), TF-IDF = TF·IDF. Rare overall but frequent in this doc → high weight.

  • Q: Why does BoW fail on "dog bites man" vs "man bites dog"?

    • A: It ignores word order/structure — both produce identical vectors. Loss of contextual/semantic information.

  • Q: Cosine similarity formula and what its values mean?

    • A: cos θ = (A·B)/(‖A‖‖B‖). +1 = same direction (most similar), 0 = orthogonal (unrelated), −1 = opposite. Distance = 1 − cos θ.

  • Q: Stemming vs lemmatisation?

    • A: Stemming = crude suffix removal ("caring"→"car"). Lemmatisation = dictionary root using POS/context ("caring"→"care"). Lemma keeps meaning.

  • Q: One sentence — what do distributed representations add over TF-IDF?

    • A: Dense learned embeddings place semantically similar words/docs near each other (king−man+woman≈queen); BoW/TF-IDF can't capture synonymy.

  • Q: Which library implements Word2Vec/Doc2Vec — and which don't?

    • A: Gensim does (plus a Google-news pre-trained model); NLTK and scikit-learn do not.

  • Q: Why must you vectorise text before SMOTE?

    • A: SMOTE interpolates in numeric feature space — you can't meaningfully oversample raw unvectorised text.

  • Cosine muddle in the transcript. The lecturer mixed "cosine" (similarity) and "cosine distance." Clean version: cosine similarity +1 = identical direction, 0 = orthogonal, −1 = opposite; cosine distance = 1 − similarity (so 0 = identical, 1 = orthogonal, 2 = opposite). For non-negative BoW vectors similarity is capped at [0,1] — which is why two semantically similar docs sharing no terms look maximally far apart (the motivation for distributed representations).
