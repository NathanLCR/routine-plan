NLP — Week 6: LLMs, Transformers & Tokenisation (+ CA1 Task 2 walkthrough)

Focus

Two-part lecture. First half: the lecturer walked through exactly how he wants CA1 Task 2 done — run the data through AI Studio auto-modelling, read the binary-classifier metrics correctly, pick 3 algorithms × 3 representations (≥9 runs), then improve on the AI Studio benchmark in Colab. Second half: the start of the LLM block — attention, transformers, GPT-2 architecture, transfer learning and tokenisation — building toward coding a GPT from scratch over the coming weeks. Sharpest warning: AI Studio reports training error; Colab reports generalised (test) error, so your Colab numbers are solving a harder problem — don't panic if they're lower, justify them ("every model is wrong, some are useful").

Key Concepts

  • AI Studio auto-modelling benchmark — paste the 9 binary-classifier results into a single benchmark sheet (numeric format). Binary only; multi-class (e.g. MIMIC) can't use it.
  • Drop KNN — performs poorly on big/high-dimensional NLP data; exclude from the grid.
  • Classification report = the confusion matrix — the reported precision/recall/F1 are for the chosen positive/most-important class; you must interpret, not just paste.
  • AUC ≥ 0.8 — the lecturer's rough "good enough" bar for the binary classifier.
  • Representation matters as much as algorithm — BoW/TF-IDF (top 1000) is the baseline; PCA-reduced and embeddings (BERT/GloVe) are the upgrades that capture meaning.
  • Transformer — architecture from Attention Is All You Need (Vaswani et al., 2017); dispenses with recurrence/convolution, relies on self-attention, parallelisable.
  • Attention — decoder gets access to all encoder hidden states (a weighted combination), removing the RNN encoder→decoder bottleneck.
  • Encoder vs decoder — BERT/DistilBERT/RoBERTa = encoder (strong for classification); GPT = decoder (next-token generation). Encoders have historically beaten decoders on classification.
  • Transfer learning for text — ULMFiT (2018) brought to NLP what was already standard in vision: pretrain LM → domain-adapt → fine-tune task head.
  • Token — a string, not necessarily a word; falls back to sub-word/character; punctuation are tokens too. Token → ID → embedding.
  • BPE (byte-pair encoding) — the tokenisation algorithm behind OpenAI's tiktoken (written in Rust, ~6× faster than the Hugging Face tokeniser).
  • GeLU — Gaussian Error Linear Unit; smooth gating, replaces ReLU in the transformer feed-forward block.
  • Perplexity — evaluation metric for the LM (will be poor on the tiny training text — expected).

CA1 Task 2 — representations (the second axis of the grid):

  • Rep 1 = BoW/TF-IDF, top 1000 features — AI Studio's default, your standard benchmark. Keep one TF-IDF rep for SHAP (carried over from W5).

  • Rep 3 = BERT or GloVe embeddings — expect better results because semantics are encoded ("man eats dog" ≠ "dog eats man", which BoW can't tell apart); a good pattern-detector should then pull signal out more easily.

Transformers — the lineage:

  • RNN limits: vanishing/exploding gradients cap depth at ~4–5 layers; inherently sequential → can't parallelise.
  • Attention fixed the encoder→decoder bottleneck by exposing all encoder hidden states to the decoder (weighted by relevance). Self-attention then removed recurrence entirely → trains much faster, parallelises.
  • Beyond text: Vision Transformers (ViT) for images, time-series, structured diagnosis. A current research student is comparing CNN vs ViT vs JEPA (LeCun) as a "beyond transformers" direction.
  • Karpathy's "Unreasonable Effectiveness of RNNs" blog recommended; he's now doing similar work on transformers.

Tokenisation & embeddings (today's code focus):

  • tiktoken uses BPE. A token is whatever string compresses well, not a linguistic word — which is why transformers generalise beyond language.
  • Pipeline: tokenise → dedupe → assign integer IDs → embed each ID as a vector. Self-attention compares the embeddings.
  • GPT-2 vocab = 50,257 tokens (the lecturer alternated 50,247/50,257 verbally — 50,257 is correct; see Open Questions). Embedding dim 768 for GPT-2 small; GPT-3 = 12,288 dim, 175B params.
  • Data prep = sliding window: input tensor and output tensor are the same span shifted by one token (next-token prediction); batches are windowed with a stride so pairs don't overlap too heavily. Train 1–2 epochs.

GPT-2 size table (lecturer):

  • small 124M — 12 heads, 12 transformer blocks, 768 dim → used for spam/ham.
  • medium 355M — 16 heads, 24 blocks, 1024 dim → used for instruction tuning.
  • large 774M; XL 1558M (1600 dim). Llama architecture is near-identical — small tweaks only.

Training data scale & provenance:

  • GPT-3 ≈ 499B tokens (lecturer's figure); Llama 1 = 1.4T, Llama 2 = 2T, Llama 3 = 15T.
  • Vendors stopped publishing training data (lawsuits). Early GPT = BookCorpus (~7,000 unpublished books); BERT = masked language modelling on BookCorpus + English Wikipedia.
  • GPT-3 paper (2020) Language Models are Few-Shot Learners — few-shot via in-prompt demos, no supervised fine-tuning. Microsoft Phi-3 (2024) — data quality over size for small models.

Hugging Face & access patterns:

  • Model hub (~2.7M models as of Mar 2026), datasets, tokenisers; pipeline for sentiment/summarisation/QA. Load pretrained models into RAM for scoring → lets a business ship a small custom LM.
  • Three ways to use an LLM: hosted (Claude/ChatGPT/Grok), local custom (Hugging Face), or API (LangChain — the chatbot exercise will wire a Neo4j knowledge graph + an LLM API).

Limits / cautions (lecturer):

  • Low-resource languages: few pretrained models, data availability is the bottleneck → big research opportunity (cited the Amharic sentiment student).
  • Bias = garbage in, garbage out (trained on open internet). Black-box explainability is a hard blocker in regulated domains (finance, healthcare).
  • On the "why can't anyone just build Claude?" question: the concept is reproducible; the engineering (numerical stability, huge-matrix ops, avoiding vanishing/exploding gradients at scale) is not casual work. "It is just computation" — powerful tool, can be misused, doesn't replace human creativity/EQ. You can't trust its output; critical interpretation is the skill.

Math / Code

# 1) Scaled dot-product self-attention (the heart of the transformer)
#    Attention(Q,K,V) = softmax( Q K^T / sqrt(d_k) ) V
#    Q,K,V are linear projections of the token embeddings; the softmax weights
#    are exactly the "weighted combination of all hidden states" idea.

# 2) Next-token data prep — sliding window (what notebook 1 builds)
import tiktoken
enc = tiktoken.get_encoding("gpt2")          # BPE, vocab = 50,257
ids = enc.encode("the heart of the city ...")
ctx = 4                                       # context window
inputs  = [ids[i:i+ctx]     for i in range(0, len(ids)-ctx, ctx)]  # strided
targets = [ids[i+1:i+ctx+1] for i in range(0, len(ids)-ctx, ctx)]  # shifted +1

# 3) Turning the GPT into a classifier = swap the head, then fine-tune it
#    out_head: Linear(768 -> 50_257)  becomes  Linear(768 -> n_classes)
#    (spam/ham => n_classes = 2); train the new last layer on labelled text.

CA1 metric reminder — read these off the confusion matrix, don't trust accuracy alone: precision = TP/(TP+FP), recall/sensitivity = TP/(TP+FN), specificity = TN/(TN+FP), F1 = 2·P·R/(P+R), target AUC ≥ 0.8.

Flashcards (SR)

  • Q: Why does AI Studio's score look better than your Colab score on the same model?

    • A: AI Studio reports training error; Colab (train/test split) reports generalised error — a harder problem.

  • Q: Which algorithm should always be in the CA1 grid for text, and why?

    • A: The feed-forward neural network — deep learning underpins modern NLP; justify the other two by family.

  • Q: What is a "token" in an LLM, and how is it different from an NLTK token?

    • A: A token is a string/sub-word chosen by BPE (not necessarily a word; punctuation counts); NLTK tokens are roughly whitespace-delimited words.

  • Q: How does attention remove the RNN bottleneck?

    • A: The decoder accesses all encoder hidden states as a weighted (relevance-based) combination, instead of one compressed final state.

  • Q: Encoder vs decoder — which for classification?

    • A: Encoder (BERT/DistilBERT/RoBERTa); GPT is a decoder (next-token generation). Encoders historically beat decoders on classification.

  • Q: How do you turn a GPT into a classifier?

    • A: Replace the final layer (768 → vocab 50,257) with (768 → n_classes) and fine-tune that head on labelled text.

  • Q: GPT-2 small vs medium config?

    • A: small 124M (12 heads/12 blocks/768 dim); medium 355M (16 heads/24 blocks/1024 dim).
