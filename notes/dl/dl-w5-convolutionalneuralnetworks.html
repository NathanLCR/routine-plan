DL — Week 5: Convolutional Neural Networks (CNNs)

Focus

This lecture covered Convolutional Neural Networks (CNNs), contrasting them with fully connected networks for image processing. It highlighted why flattening images destroys spatial structure and introduced CNN building blocks like convolution, ReLU, and pooling. The lecturer stressed understanding the core computation pipeline and mastering the output dimension formula for CA1.

Key Concepts

  • Transfer function — the weighted sum Σ(wᵢxᵢ) + b computed at a node, before activation.
  • Activation function — nonlinearity applied to the transfer function output (ReLU, sigmoid, softmax…).
  • Block of computation — one repeatable unit: weights+bias → transfer function → activation. Stacked per node and per layer.
  • Flattening — collapsing a multi-dimensional input (image) into a 1-D vector. Destroys spatial structure.
  • Convolution layer — slides a small kernel across the input, doing element-wise multiply + sum, to extract local features.
  • Kernel / filter — the small weight matrix (e.g. 3×3) convolved with the input.
  • Feature map — the output of a convolution (one per filter).
  • Stride (S)** — how many pixels the kernel shifts each step. Larger stride → smaller output, fewer computations, more lost detail.
  • Padding (P)** — border of (usually zero) values added around the input to control output size and preserve edge information.
  • ReLU — max(0, x). Replaces negatives with 0, injects nonlinearity.
  • Pooling (max pooling) — downsampling that keeps the max value in each window; reduces dimensions.
  • Local connectivity — each hidden unit looks only at a small region of the input, not the whole image.
  • Weight sharing — the same kernel weights are reused across all positions of the input.
  • Translation invariance — because weights are shared, a feature is recognised wherever it appears in the frame.
  • Hierarchical learning — early layers learn edges/lines, middle layers textures, deep layers whole objects.
  • Softmax — output activation converting scores to a probability distribution over classes.

Notes (live capture)

ANN Computation Pipeline Recap \[CA1\]:

  • The forward pass → loss → backprop → weight update is a mechanical, repeatable "block of computation" independent of data.
  • Forward pass per hidden node: (Inputs → weights, bias → transfer function) → activation function applied. This block repeats for all nodes and layers.
  • Memorize the (transfer function → activation) block, not discrete steps.
  • Backpropagation carries error backward to get gradients.
  • Weight update: w_new = w_old - η * ∂Loss/∂w (gradient descent).
  • One full pass = one iteration/epoch.

Why FC Nets Fail on Images \[CA1\]:

  • Parameter Explosion: A 256x256 image (65,536 inputs) creates an infeasible number of parameters in an FC layer, leading to overfitting.
  • Spatial Structure Loss: Flattening collapses the 2D/3D image structure, losing crucial adjacency and texture information.

Flattening Example:

  • A 3x3x1 image flattens to a 9-feature vector, losing all spatial relationships between pixels.

CNN Pipeline:

  • input image → [convolution → ReLU → pooling] × N → flatten → fully connected → softmax → output
  • Preserves spatial structure during feature extraction; flattening only occurs at the end.
  • PyTorch recommended for image processing over Keras/TF.

Convolution Operation \[CA1\]:

  • Applies a kernel (filter) across local input regions via element-wise multiply + sum, plus bias.
  • Output is a feature map, with one map per filter.
  • Example: 3x3 input, 2x2 kernel, stride 1, padding 0 results in a 2x2 output. Dimensionality reduction is a feature.

Stride \[CA1\]:

  • Controls kernel shift (1 pixel = max overlap, finest detail, biggest output).
  • Higher stride reduces output size and computation but loses detail/features. A hyperparameter trade-off.

Padding \[CA1\]:

  • Adds border (default 0) to input to control output size and/or preserve edge information.
  • padding = 1 adds a border, growing input by 2 in each dimension, enabling "same" padding to maintain output size.

Output Dimension Formula \[CA1 — must compute by hand\]:

  • O = floor( (W - F + 2P) / S ) + 1
  • Example: W=32, F=3, S=3, P=1 → O = floor((32-3+2)/3) + 1 = floor(31/3)+1 = 10+1 = 11.
  • Tip: PyTorch layer summaries show padding and stride—be ready to explain these using the formula.

ReLU \[CA1\]:

  • ReLU(x) = max(0, x). Applied after convolution.
  • Injects necessary nonlinearity; negatives are zeroed out.

Pooling / Max Pooling \[CA1\]:

  • Downsampling technique, keeping the max value in a window (e.g., 2x2).
  • Reduces spatial size, computation, retains prominent activations, adds robustness to small shifts.

Three CNN Principles \[CA1\]:

  • Local Connectivity: Each unit processes a small input region.
  • Weight Sharing: The same kernel weights are reused across all input positions, keeping parameter counts low.
  • Translation Invariance: Feature detection is independent of feature location due to weight sharing.

Hierarchical Feature Learning \[CA1 — research task\]:

  • Early layers: Lines, edges.
  • Middle layers: Textures, parts.
  • Deep layers: Whole objects.
  • Research Task: Explain what each layer represents in hierarchical learning beyond filter detection.

Classification Head (Softmax) \[CA1\]:

  • After flattening, FC layer feeds into Softmax (multi-class) or Sigmoid (binary).
  • Softmax formula: σ(zᵢ) = e^{zᵢ} / Σ_{j=1..K} e^{zⱼ}. Outputs sum to 1, forming a probability distribution.
  • The final decision layer uses these probabilities.

Bias in Convolution (Open Question):

  • How is the bias b in output = Σ(input · kernel) + b specified/chosen? (Typically, one learnable bias per filter, updated via backprop).

1D / 2D / 3D Convolution:

  • Covers sequences (1D), images (2D), volumes/video (3D).
  • RGB channels handled by kernel depth in 2D, not strictly 3D convolution.

Computation / Hardware Trade-off (Context):

  • CNNs are partly motivated by FC nets' computational cost on images.
  • Hyperparameters (stride, padding) are knobs for compute vs. accuracy.
  • Hardware constraints (memory, compute units) limit choices (kernel size, stride).
