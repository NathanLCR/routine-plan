DL — Week 7: Building Custom Models on Pre-trained Backbones, Data Augmentation & the CNN Model Zoo

Focus

Direct continuation of W6's transfer-learning thread, now fully hands-on. The central question: *how do you build a customised model on top of a pre-trained backbone (not just call ResNet50/VGG19 off-the-shelf)? Freeze the pre-trained base as a feature extractor, bolt your own head on top, and train only the new weights. Around it: a recap of to_categorical and EarlyStopping, a proper treatment of data augmentation (two APIs), and a tour of the CNN "model zoo" (VGG, ResNet, DenseNet, Inception/Xception, MobileNet…). Recurring CA1 message: source a real image dataset (Hugging Face, not built-in/Kaggle), justify every choice, and prefer the simplest model that works.*

Key Concepts

  • Customised model (on a backbone) — a pre-trained base (e.g. VGG16) used as a frozen feature extractor + a custom classifier head you design and train. Distinct from W6's "just run ResNet50 on my data".
  • Two weight sets — (1) transferred weights from the backbone (from ImageNet), set non-trainable; (2) new weights in your head, trainable. base_model.trainable = False (or layer.trainable = False) freezes the first set.
  • Why freeze — retraining the backbone is expensive and risks the weights blowing up / drifting; freezing keeps the learned features and only fits the small head.
  • weights="imagenet" — tells Keras to load weights learned from ImageNet rather than random init. input_shape must match your image size so the backbone is dimensionally compatible.
  • Custom head pattern — GlobalAveragePooling2D → BatchNormalization → Dense → Dropout → (Dense → Dropout) → Dense(softmax). Note: no convolution layers appear in your head's summary — the conv/pool stack lives inside the frozen backbone.
  • to_categorical (one-hot) — expands a single integer-label column into K columns (one per class). Needed because an ANN output layer has one node per class. Apply to y only (y_train, y_test), never X.
  • num_classes = len(class_names) — build an explicit class_names list first; one-hot width = number of classes. You must be able to state the label names in the CA presentation.
  • preprocess_input — each backbone ships its own (e.g. vgg16.preprocess_input), the most appropriate normaliser for that architecture — but limited; you may still need your own data prep depending on the images.
  • Data augmentation — synthetically expand the training set (flips, rotations, zooms) to improve generalisation/accuracy. Train data only — never test/deployment data.
  • Two augmentation APIs — (1) Keras preprocessing layers inside a Sequential (RandomFlip, RandomRotation, RandomZoom); (2) ImageDataGenerator (rescale, rotation_range, zoom_range, horizontal_flip…), sklearn-style.
  • When to augment — check per-class image counts in the train//test/ subfolders; if a class has too few images, augment it. If counts are already sufficient, you may not need to.
  • EarlyStopping (recap) — monitor a metric (val loss/accuracy), patience=N. Set epochs=15 but if no improvement after ~epoch 10 it stops — controls runtime and curbs overfitting. Watch the validation curve, not just training.
  • CNN model zoo — VGG16/19, ResNet50 (+ versions), DenseNet, Inception & Xception (Google), AlexNet, GoogLeNet, MobileNetV2, LeNet-5. They are permutations of the same blocks: differing kernel counts/sizes and ways of combining conv + max/avg pooling + dropout.
  • Channel progression — e.g. ResNet 64 → 128 → 256: structured growth matched to manageable computational cost.
  • Simplicity principle — prefer the simplest model; complexity = higher compute. Only go complex if the simple model is weak (lecturer's example: ~50% accuracy = basically a coin flip).
  • Hybrid CNNs — combining two CNN backbones is not standard (already heavy); better to improve the best single model by adding/removing layers/features. (Model fusion is common in diffusion contexts, not classic classification.)

Notes (live capture)

Building a customised model on a backbone:

  • Step 1 — define the base: VGG16(weights="imagenet", include_top=False, input_shape=...). ImageNet supplies the transferred weights.
  • Step 2 — freeze it: base_model.trainable = False. You do not retrain the transferred weights.
  • Step 3 — add your head on base_model.output: pooling → batch norm → dense(s) with dropout (lecturer used ~50% then ~30%) → softmax output sized to num_classes.
  • Step 4 — wrap into a model and summary(). No conv layers show in the head — they're inside the frozen VGG base.
  • If the model over-performs, that's a good sign your transferred features + head fit the task; you avoided random-init weight generation entirely.

to_categorical recap (why and where):

  • ANN output layer = one node per class → the target must be one-hot, not a single integer column.
  • CIFAR-10 example: y_train shape (50000,) → (50000, 10); y_test (10000,) → (10000, 10). The image tensors stay (50000, 32, 32, 3) (3 channels).
  • Workflow: build class_names, num_classes = len(class_names), then to_categorical(y_train, num_classes). For a truck image, only the "truck" column is 1, rest 0.
  • You must report the actual label names in your CA — the lecturer can't infer them.

Datasets — what to use for the CA:

  • Built-in (tf.keras.datasets: CIFAR-10/100, MNIST…) and Kaggle sets are too clean/easy — fine for demos, not for the CA.
  • A key assessed skill is sourcing a real image dataset, importing it, and doing the preprocessing yourself.
  • Source from Hugging Face → Datasets → image section (more appropriate than Kaggle for the assignment). Inspect the train//test/ folders and per-class subfolder counts.

Data augmentation — why and how:

  • Purpose: more varied examples of the same label → better recognition/generalisation, higher accuracy. Analogy: one ID photo vs many at different angles/distances → far better face recognition (the attendance-system example).
  • Especially important for sensitive tasks (e.g. disease diagnosis) where the model must handle multiple angles/shapes.
  • API 1 — Sequential([RandomFlip, RandomRotation, RandomZoom]) (Keras preprocessing layers).
  • API 2 — ImageDataGenerator(rescale=1./255, rotation_range=…, zoom_range=…, horizontal_flip=True).
  • Apply augmentation only to training data, never to test/deployment data. Place preprocess_input after augmentation; you can chain one preprocessing output into the next stage.

Model zoo + simplicity:

  • The Chapter 5 / "Python code CNN" notebook lists ~22 CNN architectures. Good customisable options: DenseNet, ResNet50, Inception/Xception.
  • All are permutations of conv + pooling + dropout with different kernel counts/sizes — don't treat them as exotic.
  • Start simple. Add complexity only if the simple model underperforms; complexity buys compute cost, not automatic accuracy.

import tensorflow as tf
from tensorflow.keras import layers, Model
from tensorflow.keras.applications import VGG16
from tensorflow.keras.applications.vgg16 import preprocess_input
from tensorflow.keras.utils import to_categorical
from tensorflow.keras.callbacks import EarlyStopping

# --- targets: one-hot (apply to y only) ---
class_names = ["airplane", "automobile", "bird", "cat", "deer",
               "dog", "frog", "horse", "ship", "truck"]
num_classes = len(class_names)
y_train = to_categorical(y_train, num_classes)   # (50000,) -> (50000, 10)
y_test  = to_categorical(y_test,  num_classes)   # (10000,) -> (10000, 10)

# --- data augmentation (TRAIN ONLY) ---
augment = tf.keras.Sequential([
    layers.experimental.preprocessing.RandomFlip("horizontal"),
    layers.experimental.preprocessing.RandomRotation(0.1),
    layers.experimental.preprocessing.RandomZoom(0.1),
])

# --- customised model on a frozen backbone ---
base = VGG16(weights="imagenet", include_top=False, input_shape=(32, 32, 3))
base.trainable = False                      # freeze transferred weights

inputs = tf.keras.Input(shape=(32, 32, 3))
x = augment(inputs)                         # augment first
x = preprocess_input(x)                     # then backbone-specific prep
x = base(x, training=False)
x = layers.GlobalAveragePooling2D()(x)
x = layers.BatchNormalization()(x)
x = layers.Dense(256, activation="relu")(x)
x = layers.Dropout(0.5)(x)                  # drop ~50% (heavy structure)
x = layers.Dense(128, activation="relu")(x)
x = layers.Dropout(0.3)(x)
outputs = layers.Dense(num_classes, activation="softmax")(x)
model = Model(inputs, outputs)

model.compile(optimizer="adam",
              loss="categorical_crossentropy",   # one-hot targets
              metrics=["accuracy"])

es = EarlyStopping(monitor="val_loss", patience=5, restore_best_weights=True)

          epochs=15, callbacks=[es])

Flashcards (SR)

  • Q: In a customised transfer-learning model, which weights are trainable and which are frozen?

    • A: The custom head's weights are trainable; the pre-trained backbone's transferred weights are frozen (trainable = False).

  • Q: Why does your model summary show no convolution layers even though it's a CNN?

    • A: The conv/pool stack is inside the frozen backbone; your custom head only adds pooling/dense/dropout/output.

  • Q: To which data split do you apply data augmentation, and why not the others?

    • A: Training data only — augmenting test/deployment data corrupts evaluation and isn't representative of real inference.

  • Q: to_categorical is applied to X or y? What does it do to CIFAR-10's y_train?

    • A: To y only. (50000,) → (50000, 10) one-hot (one column per class).

  • Q: Two Keras APIs for image augmentation?

    • A: Preprocessing layers in a Sequential (RandomFlip/Rotation/Zoom) and ImageDataGenerator (rescale, rotation_range, horizontal_flip…).

  • Q: Default model-complexity rule the lecturer pushes?

    • A: Prefer the simplest model; only add complexity if the simple model underperforms — complexity costs compute, not guaranteed accuracy.

  • Q: Why source the CA dataset from Hugging Face instead of tf.keras.datasets/Kaggle?
