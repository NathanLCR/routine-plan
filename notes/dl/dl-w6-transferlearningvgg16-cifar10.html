DL — Week 6: Transfer Learning (VGG16 on CIFAR-10), Callbacks & CA Strategy

Focus

Two threads. First, a strategic framing for CA1 dataset selection — whether a custom CNN is even justified when LLMs (ChatGPT/Gemini) can already do many image tasks, and how to pick a dataset by objective and longevity rather than at random. Second, a hands-on transfer-learning walkthrough: load CIFAR-10 from tf.keras.datasets, attach a custom classifier head on a frozen VGG16 base pre-trained on ImageNet, train with callbacks (EarlyStopping / ModelCheckpoint / ReduceLROnPlateau), and evaluate with loss/accuracy curves. Recurring CA1 message: justify your choices — dataset, architecture, loss function, and evaluation metric.

Key Concepts

  • Transfer learning — reuse a model pre-trained on a large benchmark dataset (ImageNet) and its learned weights instead of random initialisation, then bolt on a custom head for your task.
  • Frozen base / trainable = False — keep the pre-trained weights fixed (don't retrain them) to save computation; only the added head is trained.
  • Base model + custom head — pre-trained convolutional stack (feature extractor) followed by your own pooling/dense/dropout/output layers.
  • Benchmark dataset — ImageNet (~1.2M images, 1000 classes); used to learn the weights that transfer.
  • Built-in datasets — tf.keras.datasets: CIFAR-10, CIFAR-100, MNIST, Fashion-MNIST. Good for demonstrating the concept; cheap and standard.
  • One-hot encoding (to_categorical) — expands a single integer-label column into K columns (one per class), each 0/1.
  • categorical_crossentropy vs sparse_categorical_crossentropy — same loss; the first expects one-hot targets, the second expects integer targets (Keras one-hots internally).
  • Cross-entropy loss — L = -Σᵢ pᵢ · log(p̂ᵢ) over K classes; with one-hot pᵢ, only the true class term survives.
  • Weight initialisation — the classic deep-learning problem: how to set initial weights. Random sampling from U(0,1) or N(0,1) is ineffective; transfer learning sidesteps it with learned weights.
  • Standard uniform U(0,1) vs standard normal N(0,1) — two random-init distributions; conceptually very different (flat PDF on [0,1] vs bell curve centred at 0).
  • Empirical (68–95–99.7) rule — for a normal distribution: ≈68% within 1σ, ≈95% within 2σ, ≈99.7% within 3σ. (Lecturer said "65%" for 1σ — the accepted figure is ~68%.)
  • Chebyshev's inequality — distribution-agnostic bound: ≥75% within 2σ, ≥88.9% within 3σ. Weaker than the empirical rule but holds for any distribution.
  • Learning rate (α) — step size in the weight update w ← w − α · ∂L/∂w.
  • Vanishing weights / network collapse — if α is too large, weights can be driven toward 0; once weights are 0 the signal dies (0 × anything = 0) and learning stalls.
  • Callbacks — training-loop hooks: EarlyStopping, ModelCheckpoint, ReduceLROnPlateau.
  • EarlyStopping — monitor val_loss; stop if no improvement after patience epochs.
  • ModelCheckpoint — save the best weights (by monitored metric) during training.
  • ReduceLROnPlateau — shrink the learning rate when the monitored metric stops improving, to squeeze out further gains.
  • Validation set as test set — during fit, the validation split is used for evaluation each epoch; compile/fit does both backprop (train) and evaluation (val).
  • Metric choice — accuracy alone is insufficient for detection tasks; use recall (and precision) when misses are costly.
  • Argmax decoding — softmax outputs K probabilities; argmax over them gives the predicted class index.

Notes (live capture)

CA1 Strategy — Do you actually need a CNN? \[CA1 — frame your objective\]:

  • Litmus test: can ChatGPT / Gemini perform the same task on your dataset? If yes, the validity of your custom model is "at least close" to the LLM — which means the research question partly answers itself and a heavy custom CNN may not be justified.
  • LLMs are strong at OCR and context recognition in images (text, scene gist), but weak at fine-grained feature recognition in a specific part of an image (e.g. telling apart low-res CIFAR classes, or judging authenticity in a medical scan). That gap is where a CNN earns its place.
  • Loose framing the lecturer used: an LLM is effectively a subclass of these vision/API models — fine for "buddy"/general tasks, not for the specific discriminative feature you care about.

CA1 Strategy — Choose the dataset by objective and longevity \[CA1 — do not pick at random\]:

  • Have a practical objective first. A practical objective → a practical solution → something genuinely CV-worthy ("I solved a real practical question").
  • Some datasets expire. COVID/pneumonia detection is no longer a live problem ("it's gone") — the data was valid for a particular moment and has passed.
  • Some datasets are evergreen. Financial transactions, AML/KYC, fraud / account-freezing analysis, graph networks, crypto-wallet address sequences — these keep generating new kinds of data and tens of thousands of research works exist on them.
  • Motivation (digital finance context): the EU digital-euro programme (prerequisites being laid ~2027, fuller implementation toward ~2029) pushes a transition to digital finance. That transition requires AI for AML, KYC and fraud/"frozen" analysis, and creates new data structures (e.g. long wallet-address sequences) — a strong position for an ML/DL practitioner. (Treat the specific euro/cash figures the lecturer mentioned as illustrative, not exact.)
  • Takeaway: don't grab a random dataset and retrofit a CA around it — pick with care, objective-first.

Loading CIFAR-10 \[CA1\]:

  • load_data() returns four arrays: (x_train, y_train), (x_test, y_test) — same idea as a train/test split.
  • CIFAR-10: 50,000 train, 10,000 test, images 32×32×3 (the trailing 3 = RGB colour channels), 10 classes. Labels arrive as a single column of integers.
  • CIFAR-100 = 100 classes; ImageNet = ~1000 classes (the transfer-learning benchmark — you'll likely cite it in one line rather than train on it).
  • Plot a sample grid (e.g. first 20 in a 5×5 subplot). Resolution is so low that even a human or an LLM can struggle (horse vs. ? ) — which is exactly what makes these good challenge datasets.

to_categorical — why one-hot? \[CA1 — be ready to justify\]:

  • to_categorical expands the one integer-label column into 10 columns of 0/1.
  • Lecturer's framing: it's not about backprop/computation, it's about evaluation — with integer labels the confusion matrix is sparse / "ill-defined", and accuracy can wobble for reasons unrelated to the model.
  • Accurate clarification (flag for reflection): the operational reason is simpler — categorical_crossentropy requires one-hot targets, while sparse_categorical_crossentropy accepts integer targets and one-hots internally. The two losses are mathematically equivalent; the choice is just about label format. Worth phrasing it this way in your write-up rather than leaning on "ill-defined matrix".
  • So: one-hot labels → categorical_crossentropy; integer labels → sparse_categorical_crossentropy (lets you skip the explicit to_categorical call).

Weight initialisation & the σ rules \[CA1 — context for why transfer learning\]:

  • Default init samples weights randomly from U(0,1) (standard uniform) or N(0,1) (standard normal). A standard scaler maps inputs to roughly [-3, 3].
  • Normal-distribution coverage (empirical rule): ~68% within ±1σ, ~95% within ±2σ, ~99.7% within ±3σ; beyond ±3σ is <1%. (Chebyshev gives the weaker, distribution-free version.)
  • Either way, random init is just simulation — not informed by data, hence ineffective. Transfer learning replaces it: estimate weights on ImageNet via VGG16, save them, freeze them (trainable=False), and start your model from those learned weights instead of randomness.

VGG16 as base model \[CA1\]:

  • 16 weight layers = 13 convolutional + 3 fully-connected. Input shape must match your data: 32×32×3 here (VGG16's native default is 224×224 — adapt the input).
  • The convolution layers live inside the frozen base — so when asked "where is your conv layer?" in a custom model, the answer is: in the VGG16 base.
  • Customisable parts of your head: pooling type (avg/max), number and width of dense layers, activation functions, dropout rates, number of hidden layers, and the trainable flag. In ~99% of cases keep the base frozen.
  • MobileNetV2 is preferable for very large data / faster inference (pairs well with TensorFlow Lite — large drop in processing time).

Custom classifier head (example structure) \[CA1\]:

  • base_model output → GlobalAveragePooling2D → BatchNormalization → Dense(ReLU) → Dropout(0.5) → Dense(ReLU) → Dropout(0.3) → Dense(num_classes, softmax).
  • Build with Model(inputs=base_model.input, outputs=head_output); model.summary() shows the VGG16 structure already baked in plus your added layers.

Callbacks \[CA1\]:

  • EarlyStopping — monitor='val_loss', patience=5: if you set 20 epochs, it checks the window (e.g. 20→25); if accuracy/loss doesn't improve over those 5 epochs, it rolls back to the best (e.g. 20). Always monitor validation loss, not training loss.
  • ModelCheckpoint — saves the best weights (the optimal estimated weights from the trainable phase); can specify a save period.
  • ReduceLROnPlateau — when val_loss flattens, lower α to try to make further progress.

Learning rate & vanishing weights \[CA1 — "the 2-million-euro question"\]:

  • Weight update: wⱼ = wⱼ₋₁ − α · ∂L/∂w.
  • If α is too large, the subtracted term grows, weights shrink toward 0, and the network can collapse — once a weight is 0 it stops contributing (0 × anything = 0), so no gradient flows: vanishing weights.
  • When val_loss goes flat after ~10 epochs, weights have effectively converged/vanished — no further learning. Careful α control (or ReduceLROnPlateau) is how you manage it.
  • Open conceptual question the lecturer posed: what is the relationship between the learning rate and the objective (loss) — i.e. how does tuning α trade against the optimisation goal?

Compile, fit & evaluate \[CA1\]:

  • compile(optimizer, loss, metrics); fit(..., validation_split=0.2, epochs=20, callbacks=[...]). The validation split is used as the test set for per-epoch evaluation — compile/fit runs both backprop (train) and evaluation (val).
  • Loss curves: plot train vs validation loss; you want val loss to decrease then go minimal/flat. Accuracy curves: plot train vs validation accuracy. Stop at the divergence point — where validation stops tracking training (overfitting begins).
  • Metric choice: for detection tasks accuracy alone is misleading — add recall (and precision).
  • Predict: model.evaluate(x_test, y_test) then model.predict(...) returns 10 softmax probabilities per image; argmax gives the predicted class index → map back to the class name.

Math / Code

import tensorflow as tf
from tensorflow.keras import layers, Model
from tensorflow.keras.applications import VGG16
from tensorflow.keras.applications.vgg16 import preprocess_input
from tensorflow.keras.callbacks import EarlyStopping, ModelCheckpoint, ReduceLROnPlateau

# --- Data: 50,000 train / 10,000 test, 32x32x3, 10 classes ---
(x_train, y_train), (x_test, y_test) = tf.keras.datasets.cifar10.load_data()
x_train = preprocess_input(x_train.astype("float32"))
x_test  = preprocess_input(x_test.astype("float32"))
# y_train stays integer -> use sparse_categorical_crossentropy
# OR: y_train = tf.keras.utils.to_categorical(y_train, 10) -> use categorical_crossentropy

# --- Frozen VGG16 base (13 conv + 3 FC = 16 weight layers) ---
base = VGG16(weights="imagenet", include_top=False, input_shape=(32, 32, 3))
base.trainable = False  # keep ImageNet weights; ~99% of the time

# --- Custom head ---
x = layers.GlobalAveragePooling2D()(base.output)
x = layers.BatchNormalization()(x)
x = layers.Dense(256, activation="relu")(x)
x = layers.Dropout(0.5)(x)
x = layers.Dense(128, activation="relu")(x)
x = layers.Dropout(0.3)(x)
out = layers.Dense(10, activation="softmax")(x)
model = Model(inputs=base.input, outputs=out)

# --- Compile (integer labels -> sparse) ---
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])  # add Recall/Precision for detection tasks

callbacks = [
    EarlyStopping(monitor="val_loss", patience=5, restore_best_weights=True),
    ModelCheckpoint("best.keras", monitor="val_loss", save_best_only=True),
    ReduceLROnPlateau(monitor="val_loss", patience=3, factor=0.5),
]

history = model.fit(x_train, y_train, validation_split=0.2,
                    epochs=20, callbacks=callbacks)

# --- Predict: softmax over 10 classes -> argmax = class index ---
import numpy as np
probs = model.predict(x_test)
preds = np.argmax(probs, axis=1)
# Cross-entropy (K classes): L = -Σ_i  p_i * log(p̂_i)
#   one-hot p_i  -> categorical_crossentropy
#   integer y    -> sparse_categorical_crossentropy   (Keras one-hots internally)

# Weight update: w_j = w_{j-1} - α * ∂L/∂w
#   α too large -> weights -> 0 -> network collapse (vanishing weights)

# Normal coverage (empirical rule): 1σ≈68%, 2σ≈95%, 3σ≈99.7%
# Chebyshev (any distribution):     2σ≥75%, 3σ≥88.9%
