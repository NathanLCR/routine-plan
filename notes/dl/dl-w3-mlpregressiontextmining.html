DL — Week 3: MLP for Regression + Text Mining Intro

Focus

Keras ANN applied to regression (continuous target) and the start of text mining with NLTK. The sharpest warning: always scale Y separately from X in regression, and always inverse_transform predictions before reporting — output is unitless between 0–1 without it. Text mining preprocessing is positioned as a universal data-preparation problem, not a unique NLP problem; the model stage is the same across domains.

Key Concepts

  • MinMaxScaler (regression) — scales all values to [0, 1]; apply to both X and Y independently with separate scaler objects
  • inverse_transform — reverses MinMax scaling to restore original units (e.g. miles per gallon); mandatory before any prediction output
  • Separate scalers for X and Y — X and Y have different ranges; one scaler would corrupt both
  • ReLU as output activation (regression) — guarantees non-negative output; use when target is physically non-negative (e.g. MPG, price, distance)
  • Sigmoid / Softmax as output (regression) — valid if Y is scaled to [0, 1] via MinMax; requires inverse_transform after
  • compile() dual role — configures both backpropagation (loss + optimizer) AND evaluation metric; evaluation runs on a validation split within training
  • batch_size=1 ≡ SGD — Adam with batch_size=1 is stochastic gradient descent; more stable on noisy data
  • KerasClassifier — Scikit-Learn wrapper for Keras; enables GridSearchCV over epochs and batch_size
  • NLU vs NLP — NLU parses context and intent; NLP processes it; NLU is prerequisite in any chatbot/RAG pipeline
  • Stemming (Lancaster) — rule-based suffix stripping; fast, aggressive, context-blind; caring → car (wrong); not preferred
  • Lemmatization (WordNet) — dictionary + POS-aware; feet → foot, waiting → wait; context-aware; preferred
  • Stop word removal — discard high-frequency low-signal tokens
  • Custom filter — remove tokens with len < 3, punctuation, special characters; write your own function
  • Vectorizer — converts cleaned tokens to numeric representation (BoW, TF-IDF, embeddings); not covered yet, coming next sessions
  • SLM (Small Language Model) — lecturer's framing: fine-tuned SLMs more relevant than generic LLMs for secure/personalised enterprise apps under EU AI Act / GDPR constraints

Notes (live capture)

Classification → Regression: the two changes:

  • Output activation: softmax → relu (regression target must be ≥ 0)
  • Loss + metric: categorical_crossentropy / accuracy → mse or mae (same function usable for both)
  • Everything else (Sequential, Dense, compile, fit) is identical

MinMaxScaler on both X and Y:

  • In CA2 (ML), you only scaled X — correct for classical ML
  • In ANN regression, scale Y too; the network output is in [0, 1] and must be decoded
  • Formula: X_scaled = (X − X_min) / (X_max − X_min)
  • Inverse: X = X_scaled × (X_max − X_min) + X_min
  • Always define two separate scalers; never fit both on the same object

Compile and fit pattern:

scaler_X = MinMaxScaler()
scaler_y = MinMaxScaler()
X_train_s = scaler_X.fit_transform(X_train)
y_train_s = scaler_y.fit_transform(y_train.reshape(-1, 1))

model = Sequential([
    Dense(12, input_dim=X_train.shape[1], activation='relu'),
    Dense(8, activation='relu'),
    Dense(1, activation='relu'),        # or sigmoid if y is [0,1]
])
model.compile(optimizer='adam', loss='mae', metrics=['mae'])
model.fit(X_train_s, y_train_s, epochs=100, batch_size=16, validation_split=0.2)

y_pred_s = model.predict(scaler_X.transform(X_test))
y_pred   = scaler_y.inverse_transform(y_pred_s)     # ← mandatory

Hyperparameter tuning:

  • batch_size and epochs are grid-searchable via KerasClassifier + GridSearchCV
  • Same pattern as CA1 (ML) — no new API; just wrap the Keras model

Text mining — preprocessing pipeline:

  1. Lowercase all tokens
  2. Tokenise
  3. Stem (Lancaster) or Lemmatise (WordNet) — prefer lemmatisation
  4. Remove stop words
  5. Custom filter: len(token) >= 3, strip punctuation / special chars
  6. Vectorise → (coming next sessions)

Stemming vs Lemmatisation:

  • Stemmer: waiting → wait, weights → weight, care → car (wrong) — no dictionary
  • Lemmatiser: feet → foot, uses POS and dictionary; six WordNet types available
  • Rule of thumb: always use lemmatisation unless speed is the only constraint

# MinMax scaling — both X and Y for ANN regression
from sklearn.preprocessing import MinMaxScaler
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense

scaler_X = MinMaxScaler()
scaler_y = MinMaxScaler()

X_tr = scaler_X.fit_transform(X_train)
y_tr = scaler_y.fit_transform(y_train.reshape(-1, 1))

model = Sequential([
    Dense(12, input_dim=X_tr.shape[1], activation='relu'),
    Dense(8,  activation='relu'),
    Dense(1,  activation='relu'),   # non-negative continuous target
])
model.compile(optimizer='adam', loss='mae', metrics=['mae'])
model.fit(X_tr, y_tr, epochs=100, batch_size=16, validation_split=0.2, verbose=0)

y_pred = scaler_y.inverse_transform(model.predict(scaler_X.transform(X_test)))

# Lemmatisation (WordNet)
import nltk
from nltk.stem import WordNetLemmatizer
nltk.download('wordnet', quiet=True)

lem = WordNetLemmatizer()
tokens = ["feet", "waiting", "weights", "caring"]
print([lem.lemmatize(t, pos='v') for t in tokens])
# → ['feet', 'wait', 'weights', 'care']  (noun form differs from verb form)
# Note: pass pos='v' for verbs; default is noun — matters for accuracy

Flashcards (SR)

  • Q: Why scale Y in ANN regression but not in classical ML regression?

    • A: ANN output nodes produce values in [0, 1] (with sigmoid/relu); unscaled targets push the network to learn large-magnitude weights, destabilising training. Classical ML estimators fit the target scale directly.

  • Q: What is the inverse MinMax transform formula?

    • A: X_original = X_scaled × (X_max − X_min) + X_min

  • Q: Why define two separate scaler objects (one for X, one for Y)?

    • A: Each scaler stores the min/max of the data it was fit on. Fitting one scaler on both would produce incorrect inverse transforms because the stored range would be wrong for both.

  • Q: batch_size=1 with Adam is equivalent to what?

    • A: SGD (stochastic gradient descent) — one sample per weight update.

  • Q: What's the difference between stemming and lemmatisation?

    • A: Stemming is rule-based suffix stripping (fast, lossy, context-blind). Lemmatisation uses a dictionary + POS (slower, accurate, context-aware). Prefer lemmatisation unless speed is the hard constraint.

  • Q: What does compile() configure in Keras?

    • A: Two things: (1) backpropagation — loss function + optimizer; (2) evaluation — the metric computed on the validation split each epoch.

  • Q: When should you use ReLU as the output activation for regression?

    • A: When the target variable is physically non-negative (e.g. distance, price, MPG). ReLU guarantees output ≥ 0.
