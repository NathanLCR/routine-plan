RL — Week 2: Value Functions, Q-Values & MDPs

Focus

Week 2 moves from Week 1's intuition to the formal Markov Decision Process description and the two functions you'll actually compute: the value function V(s) and the action-value Q(s,a). Rewards are engineered (e.g. −1 per step), a discount/"forgetting" factor penalises longer paths, and the goal is an optimal policy π\* that maximises expected discounted cumulative reward. Two recurring lecturer themes: identify the real problem before reaching for models (the AI-in-healthcare startup stories), and RL only works while the environment stays fixed.

Key Concepts

  • Markov Decision Process (MDP) — formal RL description, the tuple (S, A, R, P, γ): states, actions, reward distribution, transition probability, discount factor
  • Markov property — the current state completely characterises the state of the world (no need for history)
  • State (S) — a snapshot of the environment (a photo of the board / a game frame)
  • Action (A) — a move available in a state (up/down/left/right; chess moves)
  • Reward (R) — scalar feedback after an action; can be negative (e.g. −1 per step)
  • Policy (π) — mapping from state to action (the strategy)
  • Optimal policy (π\*) — the policy that maximises expected discounted cumulative reward
  • Discount / "forgetting" factor (γ) — γᵗ weighting that makes shorter paths preferable
  • Value function V(s) — expected cumulative reward from state s following π; no action dependence ("how many steps to reward")
  • Q-value function Q(s,a) — expected cumulative reward from taking action a in state s, then following π; action-dependent — this is the CA requirement
  • Transition / next state (Sₜ₊₁) — the environment after an action
  • Supervised vs unsupervised vs RL — labels vs clustering vs reward-driven sequences
  • Fixed-environment constraint — a model trained on one environment breaks if the environment changes
  • Frame stacking — several frames are needed to infer velocity/acceleration (Atari ball)
  • Q-learning → Deep Q-learning — learn Q via a table first, then via a neural network
  • Tooling — TensorFlow vs PyTorch, Stable-Baselines3 (PyTorch, production), Hugging Face hosts pretrained RL models

The RL data shape:

  • Rows of (state, action, reward, next state) — not the 2-feature distance/mean math of clustering
  • State = photo of the environment; action changes it; reward scores the outcome; record the sequence
  • Following a policy produces sample trajectories/paths: s₀, a₀, r₀, s₁, a₁, r₁, …

Canonical environments (exact slide State / Action / Reward):

  • Cart-pole — State: angle, angular speed, position, horizontal velocity · Action: horizontal force on the cart · Reward: +1 each timestep the pole is upright
  • Robot movement — State: angle & position of the joints · Action: torques on joints · Reward: +1 each timestep upright + forward movement
  • Atari games — State: raw pixel inputs · Action: game controls (left/right/up/down) · Reward: score increase/decrease each timestep
  • Go — State: position of all pieces · Action: where to place the next piece · Reward: +1 if you win at the end, 0 otherwise (sparse/terminal reward)
  • Grid World — Actions {right, left, up, down}; r = −1 per transition; objective: reach a terminal state in the fewest actions

Reward engineering:

  • Chess: assign piece values, reward = (sum of my pieces) − (sum of opponent's)
  • Navigation: −1 per step ⇒ fewer steps = higher (less negative) total reward ⇒ shortest path wins
  • Balance task (cart-pole): reward for keeping the pole upright; 0/no reward when it falls
  • Robot dog: think joints/motors, not left/right — 8+ motors × speeds, brute-force combinations until it "learns to walk"; reward = balanced and moving toward the goal (multi-term reward)

Value vs Q (the core distinction):

  • V(s) = value of being in a state under the policy → in the fire-exit gridworld, V(s) = −(steps to nearest exit). No action choice involved
  • Q(s,a) = value of taking a specific action in a state, then following the policy. Many actions per state ⇒ a Q-value per (state, action) pair; the optimal policy picks argmax over actions
  • The CA needs the Q-value version, not just V

Fixed-environment constraint (kept stressing this):

  • Change the board size (8×8 → 9×9), add a second ball, or change the cart's mass → the trained model fails because the physics/coordinates it learned no longer hold
  • Autonomous-car analogy: a closed-environment demo doesn't transfer to the open world. RL requires the environment to stay the same (or you retrain)

Maths framing (kept light):

  • Markov chains underlie this (telecom, supply chains, logistics)
  • Goal stated as maximising the expected discounted sum of rewards — the expectation handles the randomness in initial state and transitions

Math / Code

MDP = (S, A, R, P, γ)
  S: states   A: actions   R: reward dist. given (s,a)
  P: transition prob. over next state given (s,a)   γ: discount factor
Markov property: the current state completely characterises the world.

Dynamics:  s_0 ~ p(s_0);   then for t = 0 until done:
  agent picks a_t ;  r_t ~ R(·|s_t,a_t) ;  s_{t+1} ~ P(·|s_t,a_t)
A policy π: S → A maps each state to an action.

Optimal policy (exact slide form):
  π* = argmax_π  E[ Σ_{t≥0} γ^t r_t | π ]
       with  s_0~p(s_0),  a_t~π(·|s_t),  s_{t+1}~p(·|s_t,a_t)

Value function — "how good is a state?":
  V^π(s)   = E[ Σ_{t≥0} γ^t r_t | s_0 = s, π ]
Q-value function — "how good is a state-action pair?":
  Q^π(s,a) = E[ Σ_{t≥0} γ^t r_t | s_0 = s, a_0 = a, π ]

Grid World (slide): 4×4 grid, two terminal states, r = -1 per transition
  ⇒ V(s) ≈ -(min steps to a terminal state); e.g. 2 steps away ⇒ V ≈ -2.
γ < 1 makes a 5-step path (γ^5·R) score higher than a 20-step path (γ^20·R).

Flashcards (SR)

  • Q: What is a Markov Decision Process?

    • A: The formal description of an RL problem — a set of states, actions, rewards, transitions to next states, and a discount factor.

  • Q: Difference between the value function V(s) and the Q-value function Q(s,a)?

    • A: V(s) is the expected cumulative reward of being in state s under the policy (no action choice); Q(s,a) is the expected cumulative reward of taking action a in state s, then following the policy. Q is action-dependent.

  • Q: What does the discount/"forgetting" factor γ do?

    • A: It weights future rewards by γᵗ so that shorter paths to the same reward score higher, making the optimal policy prefer fewer steps.

  • Q: Why does a −1-per-step reward produce shortest-path behaviour?

    • A: Every step subtracts 1, so fewer steps means a higher (less negative) total reward; the policy maximising reward minimises steps.

  • Q: Why must the RL environment stay fixed?

    • A: A policy/model trained on one environment encodes its specific coordinates/physics; changing board size, object count, or mass breaks it and requires retraining.

  • Q: How is reinforcement learning different from supervised and unsupervised learning?

    • A: Supervised uses human labels; unsupervised finds clusters/patterns without labels; RL learns from reward feedback over sequences of states and actions — you can't simply label "is this move good?".

  • Q: What is the optimal policy π\*?

    • A: The policy that maximises expected discounted cumulative reward; for a known Q, π(s) = argmax_a Q*(s,a).

  • Q: What is deep Q-learning?

    • A: Q-learning where the Q-table is replaced by a neural network approximating Q(s,a); still reinforcement learning.

  • Q: Why are several stacked frames needed in games like Atari?

    • A: A single frame can't reveal motion; multiple frames are needed to infer the ball's velocity and acceleration.
