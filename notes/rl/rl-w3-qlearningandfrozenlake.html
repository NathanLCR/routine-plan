RL — Week 3: Q-Learning, Epsilon-Greedy & FrozenLake

Focus

Week 3 takes the Q-function definition from Week 2 and shows how to fill it in through experience — the tabular Q-learning update loop. The concrete vehicle is FrozenLake (Gymnasium): a 4×4 grid, 16 states, 4 actions per state → a 64-entry Q-table, initialised to zero and updated iteratively. No neural networks yet. The lecturer made the connection to RLHF in LLMs explicit (NVIDIA podcast reference) — this is where the module is heading. Sharp warning from Week 2 carry-over: the fixed-environment constraint still applies — don't design a CA environment that changes mid-training.

Key Concepts

  • Q-table — a 2D array of shape (n_states, n_actions) storing Q(s,a) for every state-action pair; initialised to zeros; updated through episodes
  • Tabular Q-learning — the table-based variant; no neural net; scales poorly (16 states × 4 actions = 64 values, but 10k×10k becomes intractable)
  • Epsilon (ε) — the exploration-exploitation ratio: ε fraction of time the agent acts randomly (explore), (1−ε) it acts on the best known Q-value (exploit)
  • Epsilon decay — ε starts near 1.0 (pure exploration) and decreases each episode toward a minimum, so the agent shifts from discovering to exploiting as training progresses
  • Gamma (γ) — discount factor (0.9 in the demo); weights future rewards so shorter paths score higher; the agent "forgets" distant rewards
  • Alpha (α) — learning rate (0.99 in the demo); controls how much a new Q estimate overwrites the old one
  • Policy — derived from the Q-table by argmax over actions at each state; the Q-table is the policy once trained
  • FrozenLake — 4×4 Gymnasium environment; tiles: S (start), G (goal), H (hole, terminal fail), F (frozen safe); slippery variant adds stochastic transitions
  • Gymnasium (gym) — standard RL environment library; used for FrozenLake; replaces OpenAI Gym; NOT a pre-built RL algorithm library (using it is permitted)
  • Exploration vs exploitation dilemma — the restaurant analogy: try new dishes (explore) vs order your favourite (exploit); ε encodes this mathematically
  • Deep Q-learning — replaces the Q-table with a neural net; same algorithm, different function approximator; Week 3 is intentionally pre-neural

Notes (live capture)

FrozenLake environment setup:

  • 4×4 grid → 16 possible states (cells)
  • 4 actions per state: left, right, up, down → Q-table is 16×4 = 64 values
  • Q-table initialized to zeros: Q = np.zeros((16, 4))
  • State is a scalar cell index (0–15), not coordinates
  • Gymnasium's make('FrozenLake-v1', is_slippery=False) for deterministic; is_slippery=True for stochastic (harder, closer to real RL)

Hyperparameters from the demo code:

  • γ = 0.9 — "quite high"; agent forgets more slowly → longer-horizon planning
  • ε starts high (lecturer implied ≥ 0.9 or 1.0 at start of training); decays toward epsilon_min
  • α = 0.99 — aggressive update; each experience strongly overwrites prior estimate (risky in noisy environments but fine for deterministic FrozenLake)
  • All three are tunable; the CA will require comparing at least two configurations

Epsilon-greedy explained:

  • At each step: draw random number; if < ε → random action (explore); else → argmax(Q[state]) (exploit)
  • epsilon_min sets a floor — never fully stop exploring
  • Decay: ε multiplied by a decay rate each episode; lecturer showed it dropping toward the floor as training progresses
  • Intuition: early episodes = cover the whole grid; later = converge on the best known path

Q-table update (Bellman-based):

  • After taking action a in state s, observing reward r and next state s':

    • Q[s, a] += α (r + γ max(Q[s']) - Q[s, a])

  • The code in the demo had the parameters but the update was not yet wired in at the time of the transcript — students were meant to add it

Tabular Q → Deep Q (scaling argument):

  • 4×4: 64 values → trivial
  • 10,000×10,000 environment: intractable as a table → neural net approximates Q(s,a)
  • Parallelisation is the other lever: deep learning + GPU = simultaneous trajectory rollouts
  • Historical note: Q-learning tables date to ~1988–1995; deep RL is a 2013+ development (DQN, Mnih et al.)

RL in LLMs (lecturer's NVIDIA podcast reference):

  • RLHF: the "environment" is user prompts; the "reward" is human preference signal
  • The agent (LLM) generates an output; the reward model scores it; weights update via policy gradient
  • Negative reward (penalising bad answers) was said to teach faster than positive reward alone
  • OpenAI and DeepSeek use similar RLHF approaches on top of supervised fine-tuning

Lecturer's in-class FrozenLake exercise:

  • Students asked to sketch the environment on paper (not code it) — 4×4 grid, label S/G/H/F
  • The point: before writing code, the brain must represent the state space, action space, and terminal conditions
  • One student's design had no holes → trivial problem (every strategy wins); lecturer flagged this as the degenerate monopoly/tautology case

import numpy as np
import gymnasium as gym

env = gym.make("FrozenLake-v1", is_slippery=False)

n_states  = env.observation_space.n   # 16
n_actions = env.action_space.n        # 4

Q = np.zeros((n_states, n_actions))   # Q-table initialised to zeros (shown in demo)

# Hyperparameters (from demo code)
gamma       = 0.9    # discount factor
alpha       = 0.99   # learning rate
epsilon     = 1.0    # initial exploration rate
epsilon_min = 0.01
decay_rate  = 0.995  # epsilon *= decay_rate each episode

# Bellman Q-update (the part the demo code was missing — add in training loop)
# Q[s, a] += alpha * (r + gamma * np.max(Q[s_next]) - Q[s, a])

# Epsilon-greedy action selection
def select_action(state, Q, epsilon):
    if np.random.rand() < epsilon:
        return env.action_space.sample()          # explore
    return np.argmax(Q[state])                    # exploit
Q-table shape:  (16, 4)  — one row per state, one column per action
Actions:        0=left  1=down  2=right  3=up  (Gymnasium convention)
Tile codes:     S=start  F=frozen  H=hole(terminal)  G=goal(terminal,+1)

Bellman update:
  Q(s,a) ← Q(s,a) + α · [ r + γ · max_{a'} Q(s',a') − Q(s,a) ]

At convergence: π*(s) = argmax_a Q*(s,a)

Flashcards (SR)

  • Q: What is the shape of the Q-table for FrozenLake (4×4 grid, 4 actions)?

    • A: (16, 4) — one row per state, four columns for left/down/right/up.

  • Q: What does epsilon (ε) control in Q-learning?

    • A: The exploration-exploitation balance — ε fraction of steps the agent acts randomly (explore); the rest it picks the action with the highest Q-value (exploit).

  • Q: Why does epsilon decay during training?

    • A: Early in training the agent needs to explore the full state space; later it should exploit what it has learned. Decaying ε shifts the balance from random to greedy over time.

  • Q: Write the tabular Q-learning Bellman update.

    • A: Q[s,a] += α (r + γ max(Q[s']) - Q[s,a]) where α = learning rate, γ = discount, r = reward, s' = next state.

  • Q: What is the difference between tabular Q-learning and deep Q-learning?

    • A: Tabular stores Q(s,a) in an explicit table; deep Q-learning approximates Q(s,a) with a neural network, enabling larger or continuous state spaces.

  • Q: Why does the Gymnasium library NOT violate the "no pre-built RL libraries" constraint in the CA brief?

    • A: Gymnasium provides the environment (state space, step function, reward signal); it does not implement Q-learning or any RL algorithm. The algorithm must still be coded from scratch.

  • Q: What does gamma (γ) = 0.9 mean practically?

    • A: The agent discounts future rewards by 0.9 per step — a reward 10 steps away is worth 0.9^10 ≈ 0.35 of an immediate reward, favouring shorter paths.
