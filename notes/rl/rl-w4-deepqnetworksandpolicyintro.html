Key Concepts

  • Problem-first topic selection — domain → top 10–12 problems in that domain (e.g. Oracle's "12 major healthcare challenges") → pick one → search "deep reinforcement learning + <problem>". Article-first search only finds problems people already solved; problem-first can hit untouched, more important ones
  • DQN (Deep Q-Network) — neural net replaces the Q-table: input = state, output = one Q-value per action; pick argmax; train on the Bellman target
  • Frame stacking — a single Atari screenshot gives position only; ~4–5 stacked frames let the CNN infer direction, speed, acceleration (temporal information)
  • DQN loss — minimize the difference between predicted Q(s,a) and target r + γ·max_a' Q(s',a'); structurally like supervised learning (predicted vs "real" value)
  • DQN fit — discrete, limited action spaces (output layer = one neuron per action); breaks down as action space grows or becomes continuous
  • Atari result (Mnih et al.) — DQN beat human performance on >50% of Atari games; also found non-obvious optimal policies humans miss (tunnel-the-ball strategy)
  • Policy-based methods — network outputs π(a|s): a probability distribution over actions (softmax, sums to 1) instead of Q-values; e.g. up 0.9, stay 0.1, left 0
  • Continuous action spaces — describe the action distribution with μ and σ (normal distribution); policy = f(s) → distribution parameters; this is why policy methods handle continuous control where DQN can't
  • PPO (Proximal Policy Optimization) — the policy-side counterpart in the DQN-vs-PPO comparison activity; details deferred
  • Actor-critic — mentioned only as "an actor plus someone assessing the actions"; not covered yet
  • PyTorch vs TensorFlow — lecturer's heuristic: PyTorch dominates research, TensorFlow production; CA can use either (Keras on TF likely)

DQN mechanics (Atari walk-through):

  • Screenshot → CNN → state representation; stack ~5 frames for velocity/acceleration.
  • For each state, the net outputs Q for each action (left/right/stay). Going left and missing the ball → negative reward → that (s,a) gets pushed down; iterate back and forth until the net converges.
  • Q-function = for a (state, action) pair, the maximum reward obtainable; final layer returns max over Q-values for action selection.
  • Training target: r + γ·max Q(s',·) (discounted future value); minimize predicted-vs-target error — the formula-heavy slides will be re-presented with pictures in a follow-up.
  • Grid worked example (textbook p. 2018 figure): Q-values for up/left/down, highest ≈4, applying discount + reward → current position value ≈2.6.

Policy methods (preview):

  • Architecture nearly identical to DQN: input layer (e.g. CartPole: position, velocity, angle, angular velocity) → FC layers → softmax → action probabilities summing to 1.
  • Instead of "value of each action", you get "probability each action is the right one" → sample (stochastic) or argmax (deterministic).
  • Continuous spaces: output μ and σ of a normal distribution over the action — recap normal distribution and Z-scores before next classes.
  • Open question he left us: what do we supply to the network when training a policy (state? action?) — to be worked through in Python.

Math / Code

Tabular → Deep Q:
  W3: Q[s,a] += α(r + γ·max_a' Q[s',a'] − Q[s,a])      (table)
  W4: Q(s,a;θ) ≈ neural net.  Loss = E[(r + γ·max_a' Q(s',a';θ) − Q(s,a;θ))²]
      — same Bellman backup, function approximator swapped in.

DQN architecture (discrete actions only):
  state (stacked frames → CNN, or feature vector → FC)
  → hidden layers (ReLU/tanh)
  → output: |A| neurons, one Q-value per action → argmax

Policy network:
  state → FC layers → softmax → π(a|s), Σ_a π(a|s) = 1
  Continuous: net outputs μ, σ → a ~ N(μ, σ²)

CartPole state (policy example): [position, velocity, angle, angular_velocity]

Flashcards (SR)

  • Q: What replaces the Q-table in deep Q-learning, and what stays the same?

    • A: A neural net mapping state → one Q-value per action. The Bellman backup/target (r + γ·max Q(s')) stays the same.

  • Q: Why stack ~4–5 frames as the DQN input for Atari?

    • A: One frame gives position only; consecutive frames let the CNN infer direction, velocity, and acceleration (temporal information).

  • Q: What is the DQN loss conceptually?

    • A: Squared error between predicted Q(s,a) and the target r + γ·max_a' Q(s',a') — supervised-style predicted-vs-real minimization.

  • Q: When is DQN a good fit, and when does it break?

    • A: Good: discrete, limited action spaces (one output neuron per action). Breaks: large or continuous action spaces → policy methods.

  • Q: How does a policy network's output differ from DQN's?

    • A: Probabilities over actions (softmax, sums to 1) rather than values — π(a|s); sample or take argmax.

  • Q: How do policy methods handle continuous action spaces?

    • A: Output distribution parameters (μ, σ of a normal); sample the action from N(μ, σ²).

  • Q: What was the Atari DQN milestone?

    • A: DQN exceeded human performance on >50% of Atari games and discovered non-obvious optimal strategies (e.g. tunneling the ball).

  • Q: What's the lecturer's problem-finding method for CA1?

    • A: Domain → list the domain's top 10–12 business problems (reputable source) → pick one → then search for RL articles. Problem-first, not article-first.

  • Q: Insider-threat example — state, action, reward?

    • A: State: account × table × settings combination; actions: open/change-encryption/change-rights/export; reward +1 for catching a flagged combination. Rewards must be numeric and plotted cumulatively.

  • Q: CA1 key dates and team size?

    • A: Teams 3–5; submission Week 7 = 5 July 2026; presentation + feedback Week 8 ≈ 8 July. Core deliverable centers on deep Q-learning.

  • Q: PyTorch vs TensorFlow per the lecturer?

    • A: PyTorch → research environments; TensorFlow → production. Either acceptable for the CA; next lecture codes DQN in TensorFlow.
